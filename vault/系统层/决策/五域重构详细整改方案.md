# 五域重构详细整改方案

## 决策博弈：为什么要现在做

重构不是拍脑袋。2026年5月当前系统状态：

- **5个Profile** 承载了 **33个Worker模块**，其中21个注册了Handoff路由
- **20+ SOP Pack** 散落在各Profile，触发词重叠率高达40%
- **19个Cron作业** 的归属没有按业务域划分
- **飞轮管线**（情报→内容→增长）是跨域串联的，但断链后无人认领

核心博弈点：是逐步修修补补，还是一次性重构？

**决策依据**：CEO路由的"猜谜"问题不是修一个两个触发词能解决的——获客三路由（ads/growth/crm）打架、接单三路由（bd/shop/order）打架、内容全域归属不明。这些是结构性冲突，非补丁可解。

**决策结果**：一次性重构到5域+1枢，不留过渡态。

## 重构三原则（不可妥协）

### 原则一：付钱方唯一确定

当一个任务来了，先问「这个任务的付钱方是谁」：
- 教育机构付钱 → 墨育
- 个人粉丝付钱 → 墨媒
- 台湾/东南亚用户付钱 → 墨海
- 看情报的从业者付钱 → 墨研
- 其他一人公司付钱 → 墨创

付钱方唯一确定，域就唯一确定。这是最硬的边界判断规则。

### 原则二：内容自带，不设独立内容域

「全媒体业务」这个域被证明是错误的抽象——内容是渠道不是业务。每个业务域自带内容能力：

- 墨育·墨料：只产出招生用途的内容
- 墨媒·墨笔：只产出个人IP品牌内容
- 墨研·墨简：只产出情报简报内容
- 墨海·墨译：只产出台繁/东南亚适配内容
- 墨创：不直接对外产出内容

### 原则三：变现路径独立

每个域有自己独立的变现路径，不需要依赖其他域才能产生收入：

| 域 | 变现路径 | 客单价 |
|----|---------|-------|
| 墨育 | 增长工具SaaS + 增长咨询 + Leads分发 | ¥500-2000/月 |
| 墨研 | 知识星球订阅 + 情报简报 + AI工具培训 | ¥299-599/年 |
| 墨媒 | 知识付费课程 + 私董会 + 品牌合作 + 接单 | 按项目 |
| 墨海 | 台湾内容订阅 + 本地化服务 + 东南亚Leads | 按市场 |
| 墨创 | SaaS工具化 + 「一人公司AI化」培训 | 按产品 |

## 风险与兜底

### 风险1：重构期间系统不可用

**风险等级**：中
**概率**：40%（预计3天核心不可用）

**缓解措施**：
- 阶段0先做完整备份（`cp -a ~/.hermes ~/backups/`）
- 每个阶段独立验证，不跳过验证进入下一阶段
- 任一阶段验证失败 → 回滚到上一阶段备份

**回滚方案**：
```bash
# 全量回滚
hermes gateway stop --all
rm -rf ~/.hermes/
cp -a ~/backups/hermes-pre-restructure-$(date +%Y%m%d)/ ~/.hermes/
hermes gateway start --all
```

### 风险2：Worker逻辑迁移丢失功能

**风险等级**：中
**概率**：25%（合并Worker时遗漏边缘功能）

**缓解措施**：
- 废弃Worker先 rename 为 `_deprecated_*` 而不是删除
- 新Worker import 旧Worker的核心函数，不重写
- 生产环境保留 `_deprecated_*` 至少30天

### 风险3：Cron作业归属错误导致漏执行

**风险等级**：高
**概率**：20%（修改归属后权限或环境变量不匹配）

**缓解措施**：
- 每个Cron修改后在目标Profile的终端中手动执行一次，验证结果
- 修改后观察7天，建立监控：如果某作业连续3次无产出 → 飞书告警

### 风险4：触发词边界仍然模糊

**风险等级**：低（因为有"付钱方唯一"原则兜底）
**概率**：15%

**缓解措施**：
- 每个域的 System Prompt 中硬编码"付钱方判断规则"
- 边界重叠时，路由到 CEO中枢，由中枢根据"付钱方"二次分发
- CEO中枢的DARE路由升级到四层（Domain → Activity → Role → Execution）
