## 二、根因分析（5Why法进阶版）

### 2.1 主问题链：为什么5天内零有效内容产出？

**Why1**：为什么5/15-5/21共6天，只发布了2篇内容，且后续5天零发布？
→ 发布时间线：5/15发第1篇 → 5/16发第2篇 → 5/16后发布适配器Cookie失效 → 5/18 copywriter产出新内容 → 发布适配器无法使用 → 积压至今

**Why2**：为什么Cookie失效后没人去修复？
→ 两次动作尝试（5/18、5/20）均失败。第一次尝试 `xhs login` 报错（Python版本不兼容）。第二次尝试手动更新Cookie文件，未完成。后续无人跟进。

**Why3**：为什么没有「Cookie失效」的告警机制？
→ Monitor状态检查仅在数据采集时被动发现（last_checked会更新），没有主动心跳检测。5/18 21:00后Monitor停止更新，无人主动排查。

**Why4**：为什么没有降级方案（人工发布流程）？
→ 架构设计假定「全自动发布」是唯一通路，未考虑Cookie过期/API变更等现实情况。没有「输出内容→复制到剪贴板→人工粘贴发布」的SOP。

**Why5**：为什么全自动设计中没有容错机制？
→ 内容飞轮的设计对标大厂CI/CD流水线（自动构建→自动测试→自动部署），但缺少预发布环境验证、回滚机制、和「手动挡」备用流程。对于一个人的初创账号，过度自动化反而成为瓶颈。

**根因结论**：**「零内容产出」的根因不是能力不足，而是自动化架构缺少容错层和降级层。** Cookie过期是必然事件（小红书Cookie有效期约7天），系统应该在此类事件发生时自动切换为半自动模式，而非完全瘫痪。

### 2.2 次问题链：为什么已发布的内容零互动（第一个数据验证点）？

**Why1**：为什么「我用Hermes搭了一个AI公司」只有4浏览？
→ 小红书初始流量池200-500曝光，4浏览说明笔记未进入推荐池——可能被标记为低质内容（纯文字、无图片、标题平淡、缺少互动引导）

**Why2**：为什么未被系统推荐？
→ 小红书CES评分中，原创度(30%)+互动深度(25%)+完播率(20%)+停留时长(15%)+分享转发(10%)。纯文字笔记在停留时长和完播率上天然劣势（完播率=0，无视觉停留）。且0互动导致曝光权重归零。

**Why3**：为什么没有设计互动钩子和视觉元素？
→ 两篇均为text mode发布（无图片）。内容结尾有CTA「关注我」，但没有评论引导、没有收藏暗示、没有收藏价值的设计。

**Why4**：为什么发布前没有检测这些缺陷？
→ 内容生产（墨笔文创）产出文案后直接送发布适配器，中间缺少「发布前 checklist 」——标题是否吸引？封面是否合格？互动钩子是否存在？发布时段是否最佳？

**Why5**：为什么没有第一条内容的复盘？
→ 因为Monitor 5/18后停更，系统未感知到「4浏览0互动」的失败。如果Monitor正常心跳，5/18当晚就应该触发T4告警。

**根因结论**：**「零互动」的根因是内容策略错误（冷启动阶段发纯文字工具展示）+ 质量门控缺失（无发布前checklist）+ 数据反馈断裂（Monitor停更导致失败无感知）。**

## 二、根因分析（5Why）

### 2.1 为什么内容产出为零（主链条）

**Why1**：为什么分发层没有任何发布记录？
→ 分发层(10:30)的发布适配器(publish_to_xiaohongshu.py)可能未接入真实Cookie/Token，或从未被cron触发。

**Why2**：为什么无人发现发布层断裂？
→ 飞轮缺少「是否成功发布」的监督机制。copywriter_output.json→发布适配器→publish_results.json的链路上没有T4告警。

**Why3**：为什么内容层的质量这么差（标题拼接关键词）？
→ 内容生产者(墨笔文创)直接从intelligence.json提取热词作为标题主体，但热词本身是抖音热搜原文(如"🔥 巴西队世界杯26人名单")，未经过滤。

**Why4**：为什么情报层采集的数据不加赛道过滤？
→ 情报管道设计的核心指标是「采集量」(total_items_collected=854)，没有「赛道相关度评分」这一关键质量门控。

**Why5**：为什么没有赛道相关度评分？
→ 内容情报管道的SOP中，数据采集→RRF排序→选题推荐的链路中，缺少「赛道概念映射」中间层。采集器拉取的是平台热搜原始数据，而非垂域热词。

**根因结论**：飞轮缺失「赛道对齐」这个元步骤。情报层无过滤导致整条链路的数据污染，内容层无质量门控导致低质内容通过，分发层无监控导致断裂无人知。

### 2.2 为什么数据反馈闭环被污染（副产品链）

**Why1**：为什么analytics_feedback中抖音30条全部是娱乐热搜？
→ generate_analytics_feedback.py直接消费intelligence.json的hot_topics，未做领域过滤。

**Why2**：为什么intelligence.json的hot_topics全是娱乐？
→ collect_intelligence.py的抖音adapter直接拉取热搜榜单(公开API)，榜单自动含地震/宠物/明星等泛内容。

**Why3**：为什么没有在分析脚本中加领域过滤？
→ generate_analytics_feedback.py的filtered_counts字段仅统计非核心领域的量(50/61是「其他」)，但未阻断它们进入标题公式反馈。

**根因结论**：分析脚本的设计偏向「数据完整性」(所有源都分析)，而非「数据纯净度」(只分析赛道相关数据)。需要增加strict_domain_filter模式。
