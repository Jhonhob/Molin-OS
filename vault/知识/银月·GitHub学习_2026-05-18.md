## 二、核心架构模式（3个跨项目共同模式）

### 模式1 — 管道化分层架构
三个项目均采用严格的管道化设计，数据/任务逐层流动：

- **qiaomu**: 输入检测 → 内容获取 → 格式转换 → NotebookLM上传 → 生成 → 下载（6步管道）
- **superpowers**: 头脑风暴 → 计划编写 → 子Agent开发 → TDD循环 → 代码审查 → 分支收尾（7步管道，HARD-GATE门控）
- **PraisonAI**: Agent定义 → Task分配 → AgentFlow编排(路由/并行/循环) → 执行 → Handoff传递

**共同特征**：每一步都是独立模块，可替换/可测试，且有明确的输入/输出契约。每个项目都有强制门控机制确保步骤顺序。

### 模式2 — 声明式配置驱动
三个项目均采用声明式配置替代编程式配置：

- **qiaomu**: detect_input_type() 的15种输入类型映射表 + generate_questions_progressive() 的问题模板
- **superpowers**: YAML元信息头(SKILL.md) + plugin.json跨平台注册 + hooks.json会话钩子
- **PraisonAI**: agents.yaml声明Agent定义 + YAML工作流配置 + MEMORY_PRESETS参数预置

**共同特征**：配置与代码分离，运营人员可通过改YAML/JSON调整行为，无需修改核心代码。

### 模式3 — 容错优先的级联降级
三者都采用"宁可多做一层也不单点失败"的容错哲学：

- **qiaomu**: 6层级联付费墙绕过 + CAPTCHA检测 + 内容有效性校验 + Token自动刷新
- **superpowers**: HARD-GATE硬性约束 + 子Agent状态码(BLOCKED/NEEDS_CONTEXT) + 验证铁律
- **PraisonAI**: 结构化异常层次(6种) + Doom Loop检测 + Shadow Git Checkpoints + Heartbeat

**共同特征**：错误不是异常，是预期的一部分。每一层都有明确的失败检测和降级路径。

## 三、差异创新

### qiaomu 独有的创新
- **6层级联付费墙绕过引擎**：从代理服务→Bot UA→通用绕过→archive.today→Google Cache→本地agent-fetch，逐层fallthrough
- **三轮递进深度分析框架**：概览(4题)→深度(5题,按内容类型分叉)→综合(3题)，输出结构化JSON
- **MCP服务器扩展**：提供微信公众号抓取的MCP服务器，展示Agent与外部服务混合集成模式

### superpowers 独有的创新
- **HARD-GATE门控机制**：在技能文件中明确嵌入`<HARD-GATE>`块，禁止跳过任何强制步骤，违反即删除代码重新开始
- **反模式清单(Anti-Pattern Registry)**：每个技能内置反模式表格，捕捉Agent可能使用的偷懒理由（如"这个简单，不用写测试"）
- **子代理隔离+两阶段审核**：每个任务派发全新子代理（避免上下文污染），先做规范审核再做质量审核

### PraisonAI 独有的创新
- **AgentFlow流水线控制流原语**：Route/Parallel/Loop/Repeat/If 等声明式控制流节点，形成DAG
- **Handoff传递模式**：Agent间无缝对话传递（含循环检测），支持并行handoff
- **5层包架构**：从最轻量的SDK(praisonaiagents)到CLI层到TS/Rust跨语言到平台层，不同层解决不同粒度的编排需求
- **Doom Loop Detection + Shadow Git Checkpoints**：自动检测死循环Agent并恢复，自动创建回滚点

## 四、可直接复用的方法论（6项，按优先级排序）

### 1️⃣ Agent技能标准化体系（来自superpowers）
**问题**：当前3个Worker（墨笔文创、墨图设计、墨播短视频）虽然各有SKILL.md，但没有统一的跨Worker技能标准
**方案**：将superpowers的SKILL.md格式引入：YAML头(name+description触发条件) + Markdown正文(Checklist+流程图+铁律+反模式)
**对我方价值**：让所有Worker有统一的技能定义规范，Agent能自动识别何时激活哪个技能

### 2️⃣ 内容自动化处理管线（来自qiaomu）
**问题**：目前内容获取依赖手动搜索或固定RSS源，缺乏自动化的多源内容抓取→统一化→转产管线
**方案**：复刻qiaomu的6层级联抓取引擎 + 输入统一化模式（所有异构来源→纯文本→附带元数据头：来源/时间/标题/长度）
**对我方价值**：情报层(intelligence)可以直接嵌入这套管线，自动从付费墙内容、播客、微信公众号获取素材

### 3️⃣ 级联降级容错哲学（三个项目共有）
**问题**：当前Worker的错误处理多为单点重试，缺乏级联降级路径
**方案**：在每个Worker的执行管线中加入"如果A失败→尝试B→尝试C→报告失败"的级联策略，每步有明确的失败检测
**对我方价值**：内容飞轮更健壮，不会因为一个数据源失效就中断整条管线

### 4️⃣ YAML驱动的工作流编排（来自PraisonAI）
**问题**：当前内容飞轮是代码级硬编码的"情报→内容→分发→数据回收"
**方案**：用YAML声明式定义内容流水线：角色(编辑/写作/设计/发布) + 任务(研究→写作→审核→发布) + 控制流(并行/循环/条件)
**对我方价值**：运营人员可调整YAML改变内容飞轮行为，无需修改核心编排代码

### 5️⃣ 两阶段审核模式（来自superpowers）
**问题**：当前内容审核只有一道质量门槛
**方案**：拆为两阶段——先审核"是否符合规格"（运营规范/品牌调性），再审核"内容质量"（表达/结构/数据准确性）
**对我方价值**：内容质量从单点检查升级为双保险，降低翻车概率

### 6️⃣ 三轮递进分析框架（来自qiaomu）
**问题**：当前深度分析只有一个层面的分析
**方案**：复刻qiaomu的generate_questions_progressive()方法论——概览(4题,建立框架) → 深度(5题,按内容类型分叉) → 综合反刍(3题)
**对我方价值**：每日学习分析的深度和质量将显著提升

- **验证铁律**（superpowers）："没有验证证据就不能声明完成"——可引入内容运营的质量验证清单
- **Token自动刷新**（qiaomu）：JWT Token过期前300秒自动刷新——可引入所有外部API调用的Token管理

1. **全媒体运营专用Agent编排框架**：目前没有专门针对内容运营场景的Agent编排框架。CrewAI/PraisonAI/AutoGen都是通用编排，没有一个预设了"内容策划→写作→设计→分发→数据回收"管线的编排框架

3. **付费内容抓取+转产一体化**：qiaomu解决了抓取和转NotebookLM，但没有解决抓取后→转产为短视频/图文笔记的闭环
