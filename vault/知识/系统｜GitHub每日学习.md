    31|## 二、核心架构模式
    32|
    33|### 模式1：Pipeline分段式架构（3/3项目共用）
    34|所有项目都采用pipeline/workflow的分阶段架构：
    35|- Pixelle-Video：8步管线（setup→generate→title→visuals→storyboard→produce→post→finalize）
    36|- RedInk：3步管线（大纲→文案→批量图片）
    37|- PraisonAI：5种编排模式（Sequential→Hierarchical→Route→Parallel→Evaluator-Optimizer）
    38|
    39|启示：墨麟的Worker应该统一采用Pipeline模式，定义标准生命周期方法。
    40|
    41|### 模式2：YAML声明式配置驱动（3/3项目共用）
    42|- Pixelle-Video：config.example.yaml → Pydantic校验
    43|- RedInk：text_providers.yaml + image_providers.yaml 双配置
    44|- PraisonAI：agents.yaml 声明Agent角色/目标/工具/任务
    45|
    46|启示：墨麟的Worker配置和Agent定义可以统一为YAML格式。
    47|
    48|### 模式3：工厂模式+插件化热插拔（3/3项目共用）
    49|- Pixelle-Video：管线工厂注册 + ComfyKit懒加载（配置MD5检测自动重建）
    50|- RedInk：ImageGeneratorFactory 支持Google/OpenAI/通用API动态扩展
    51|- PraisonAI：FrameworkAdapterRegistry + 懒加载（CrewAI/AutoGen/PraisonAI三套后端）
    52|
    53|启示：墨麟各Worker的API提供商可抽象为统一工厂接口，热切换零重启。
    54|
    55|### 模式4：并发控制+限流（3/3项目共用）
    56|- Pixelle-Video：asyncio.Semaphore（默认1，最大10并发）
    57|- RedInk：ThreadPoolExecutor + MAX_CONCURRENT=15
    58|- PraisonAI：Parallel编排模式，多Agent并行执行
    59|
    60|启示：所有Worker都需要统一的并发控制基类。
    61|
    62|### 模式5：三级错误隔离体系（3/3项目共用）
    63|- Pixelle-Video：管线级try/except → 帧级try/except → 持久化不阻断主流程
    64|- RedInk：状态机（DRAFT→GENERATING→COMPLETED/PARTIAL/ERROR）
    65|- PraisonAI：Doom Loop Detection → Shadow Git Checkpoint → Auto Rollback
    66|
    67|启示：墨麟需要建立统一的错误隔离和降级机制。
