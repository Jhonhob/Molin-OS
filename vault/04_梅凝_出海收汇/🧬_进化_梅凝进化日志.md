## 💡 心得（差異化視角）
---

### 核⼼發現 1：ZHTW 是打破「在地化瓶頸」的關鍵

過去 2 週，我們一直用自建 120+ 組用語對照表做繁中轉換，覆蓋率約 95%。ZHTW 的 31K 詞條直接填補了那 5% 的盲區——尤其是數學/工程/醫學等專業文本中的繁簡差異。

**行動**：下一次在地化 Pipeline 迭代時，在 `taiwan_localize_reflect.py` 中集成 `pip install zhtw` 做前置過濾層，再搭配我們的語氣檢測 + 敏感話題過濾。

**評估**：ZHTW 沒有 Star 數，可能較新或缺乏社群認證。需先測試其 1 億字零錯轉的説法是否站得住腳。

### 核⼼發現 2：JTA Reflection 機制的取捨

JTA 的 Agentic Reflection（自我反思）雖能提升翻譯品質，但每次需 3x API calls：
- Pass 1：初始翻譯
- Pass 2：反思（找錯誤/不一致）
- Pass 3：修正翻譯

**決策博弈**：只在高價值內容啟用 Reflection → 定義「高價值」為：Vocus 長文（>2000 字）或 Shopee 旗艦店商品描述（>500 字）。一般 LINE 推文走普通翻譯即可。

### 核⼼發現 3：Nuwa-Skill 的整合瓶頸

5/18 分析了 Nuwa-Skill（19.5k⭐）的完整架構，5/19 制定了 delegate_task 模擬方案。

**當前阻滯**：Nuwa-Skill 依賴 Claude Code 環境（`npx skills add`），而我們主機尚未安裝 Claude Code → 等待老墨授權安裝。

**替代方案**：若遲遲無法安裝 Claude Code，可改用 Spiral 的「直接蒸餾」模式——用 Hermes 的 delegate_task + web_search 模擬 Nuwa-Skill 的 6 Agent 並行調研，輸出結構化 DAG。

### 核⼼發現 4：市場數據的差異化視角

- **Shopee 內容質量分+30%**：這不是普通的演算法更新，而是平台從「價格戰」轉向「內容戰」的標誌。對梅凝策略的含義：內容行銷不再是加分項，而是生存項。
- **數發部 60 億補助**：可以作為內容鉤子，但關鍵是「補助門檻」——中小創作者 vs 大型內容工作室的申請難度不同。需要實際查閱申請文件。
- **Temu 入泰**：低價戰的威脅被高估了——Temu 在美國的退貨率高達 30%，台灣/泰國用戶對退貨效率的容忍度更低。我們的策略應強調「**品質內容 → 信任建立 → 降低退貨率**」的邏輯鏈。

## ⚠️ 盲區識別（認知邊界）
---

### ❌ 盲區 1：ZHTW 實際效果未驗證

雖然理論上 ZHTW 比 OpenCC 精準 10 倍，但**未實際 pip install 測試**。可能問題：
- 與我們的 120+ 用語表有衝突（雙重轉換造成錯誤）
- 語境感知能力未知（「程式」是「程式設計」還是「program」？）
- 性能開銷（31K 詞條比對的耗時 vs 我們目前的簡單字典查詢）

**補救**：下一次 session 的第一行動是 `pip install zhtw` 並跑一批測試用例。

### ❌ 盲區 2：越南文/泰文 NLP 工具稀缺

第六期研究的終結論：越南文和泰文的專用 NLP 開源工具**極度稀缺**。
- 目前方案：依賴 LLM API（Gemini / GPT）做越/泰內容
- 但 API 成本 —— 越/泰語每字成本比中/英高 2-3 倍
- 不知道是否有本地化團隊使用其他工具（如 VinAI Research 的 PhoBERT？）

**補救**：下期研究加入關鍵詞「VinAI PhoBERT vietnamese NLP」「Thai NLP library」「PyThaiNLP」。

### ❌ 盲區 3：泰國數位平台稅 14% 的細節

報告中記錄了泰國 5/20 通過 14% 平台稅，但：
- 是否回溯徵收？（即 5/20 之前的交易是否免稅？）
- 台灣賣家是否需要泰國稅號？
- 如果透過 Shopee 代收代繳，佣金結構是否調整？

**補救**：這屬於政策細節，需要閱讀原文（泰國稅務廳公告）而非二手新聞。LEGAL 模組應當納入此類稅務合規要求的詳細審核。

### ❌ 盲區 4：Nuwa-Skill 的蒸餾成本

我一直在強調 Nuwa-Skill 的「6 Agent 並行調研」架構，但未評估：
- 一次完整蒸餾的 API 成本（6 Agent × 多輪調研 + 三重驗證 + 雙 Agent 精煉）
- 蒸餾出來的 Skill DAG 是否真的能直接嵌入我們 Pipeline 的 Step 3

**推測**：完整的「台灣在地化專家蒸餾」可能需要 50-100 次 API 調用 + 數百萬 token。在不確定 ROI 之前，應先做一次 Mini 版（2 Agent, 2 層提取）快速驗證可行性。

### ❌ 盲區 5：記憶空間接近滿載

MEMORY.md 已達 ~9,500 字符（上限 22,000 字符 ≈ 43%）。但 5/15-5/20 共 6 期的學習沉澱持續累積。目前的策略是將長篇內容寫入 Obsidian 而非 memory。

但**memory 的剩餘空間 (~12,500 字符) 是否足夠未來 2-4 週使用？**

**估算**：每期 GitHub 學習沉澱約 2,000-3,000 字符 → 約 4-6 期後填滿。屆時需要清理舊記錄或壓縮格式。
