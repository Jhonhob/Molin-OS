3. **飞轮接力**：研究任务(07:30-08:30)的输出 → 被业务任务(10:00-18:30)消费 → 业务反馈 → 晚间学习进化(21:00)蒸馏吸收

5. **运行序号追踪**：每次cron执行带上运行序号，便于追踪和回滚

# 定时任务管理标准

## 背景：为什么需要这套定时任务架构

**S — 情境**：墨麟OS是一个持续运行的 AI 驱动操作系统，依赖 7 个定时任务维持记忆同步、知识采集、版本备份和合规检查等核心能力。这些任务共同构成了系统的"代谢循环"——一旦某个任务停滞，上游依赖链上的所有节点都会连锁失效。

**C — 并发症**：初期采用手动触发 + 系统 cron（macOS launchd）混合模式。暴露三个问题：① 开发者在本地终端手动执行脚本，忘记调度后记忆碎片化；② 任务失败无告警，直到下游依赖报错才被发现；③ 项目迁移设备后 cron 配置丢失，需手动重建。

**Q — 核心问题**：如何在多设备、无固定主机的环境下，保证定时任务的可观测性、可恢复性和可审计性？

**A — 解决方案**：统一接入 Hermes cron 调度引擎，所有任务通过 `hermes-agent` 声明式配置注册，日志集中写入 iCloud，失败自动告警，跨设备 status 随 Obsidian 仓库同步。

---

## 架构决策记录

| 决策 | 选项 | 选择理由 |
|------|------|----------|
| 调度引擎 | **Hermes cron** vs. 系统 cron / launchd | Hermes cron 在 iCloud 同步目录下声明式注册，设备迁移零配置；统一告警通道；任务元数据（执行时间、状态、日志）自动写入 Obsidian，天然可审计 |
| 日志存储 | **Obsidian 文件 + stdout** vs. syslog | 日志与知识库同目录，便于 AI Agent 检索；syslog 在 iCloud 同步场景下权限复杂 |
| 任务标记 | **16 位 hex job ID** vs. 名称哈希 | 固定 ID 便于日志检索和告警引用；不会因脚本路径变更而失效 |
| 执行超时 | **Hermes 内置 timeout（默认 300s）** vs. 外部 timeout 包装 | 统一在调度层处理，避免每个脚本自行实现超时逻辑 |
| 失败重试 | **指数退避 3 次** vs. 固定 1 次 | 瞬态失败（网络抖动、率限）自动恢复；持久失败进入告警矩阵 |
| 依赖同步 | **Hermes 调度器内部 wait_for** vs. 脚本级 sleep | 声明式依赖链，调度器串行化执行，避免竞态 |

### 折衷记录

1. **单点依赖**：Hermes cron 依赖 `hermes-agent` 进程存活。如果 Agent 崩溃，所有定时任务停摆 → 通过 `keep_alive: true` + launchd 兜底重启。
2. **重复执行风险**：Agent 重启后若未正确清理上一轮状态，可能重复触发同一时间窗口的任务 → 每任务记录 `last_run_at`，启动时跳过时间戳重合。
3. **秒级精度不足**：Hermes cron 精度在 10-30s 级别，无法满足秒级调度 → 当前任务无秒级需求，可接受。

                      ↓
┌─────────────────────────────────────────────────────────────┐
│                    Git 备 份                                  │
│                    5cd81602c531                              │
│                    每日 02:00                                  │

**关键依赖规则**：

1. **记忆同步 → Git 备份**：软依赖。Git 备份运行时自动包含记忆同步产生的 Obsidian 变更；如果记忆同步失败，Git 备份仍会运行（仅备份已存在的数据）。
2. **跨线请求轮询 → 记忆同步**：新请求写入后，下次记忆同步会纳入处理。如果轮询失败，记忆同步不受影响。
3. **arXiv / 价格 / GitHub 学习 → 无下游**：三者均为叶子节点，失败不影响其他任务。
4. **Vault 合规 → 无下游**：独立扫描任务，失败不影响任何流程。

## 风险分析

### R1: Cron 守护进程崩溃

| 属性 | 说明 |
|------|------|
| **风险** | `hermes-agent` 进程异常退出，所有定时任务停摆 |
| **概率** | 低（< 1 次/月） |
| **影响** | 所有定时任务停止，直到 Agent 被手动或自动重启 |
| **检测** | macOS launchd 自动重启（`KeepAlive=true`）；如果重启失败 → 无响应超过 1 小时 → 告警 |
| **缓解** | launchd plist 配置 `KeepAlive` + `ThrottleInterval`；双 Agent 冗余（待实施） |
| **恢复** | `launchctl load ~/Library/LaunchAgents/com.nous.hermes.plist` |

### R2: 重复执行（Duplicate Execution）

| 属性 | 说明 |
|------|------|
| **风险** | Agent 重启后，时间窗口重叠导致同一任务被执行两次 |
| **概率** | 中（每次 Agent 重启都可能触发） |
| **影响** | 轻度：Git 备份 push 冲突；中度：记忆同步写入重复数据；重度：API 调用产生双重计费 |
| **检测** | 每任务记录 `last_run_at`；调度器启动时检查时间戳重合 |
| **缓解** | Hermes cron 内置去重逻辑；幂等设计（记忆同步 upsert 而非 insert） |
| **恢复** | 手动删除重复数据；调整 `last_run_at` |

### R3: 任务超时（Job Timeout）

| 属性 | 说明 |
|------|------|
| **风险** | 外部依赖（API、网络、LLM）响应慢导致任务超过默认 300s 超时 |
| **概率** | 中（LLM API 高峰期明显） |
| **影响** | 单次任务被调度器 kill，标记为 failed；不影响其他任务 |
| **检测** | 调度器监控执行时长，超时自动 SIGTERM → SIGKILL |
| **缓解** | 可配置超时上限；长时间任务分解为子步骤（如 arXiv 扫描已拆分为 fetch/parse/write） |
| **恢复** | 下次调度自动重试；手动 `hermes-agent cron run` 指定更长超时 |

### R4: 日志膨胀

| 属性 | 说明 |
|------|------|
| **风险** | 高频任务（跨线请求每 15 分钟）日志无限增长，消耗 iCloud 空间 |
| **概率** | 高（长期运行必然发生） |
| **影响** | iCloud 存储爆满 → Obsidian 同步异常 → 记忆同步写失败 |
| **缓解** | 日志自动轮转（每 1000 行切割，保留最近 7 天）；成功行压缩为单行摘要 |
| **当前状态** | 2026-05 日志目录大小约 12MB，轮转策略已生效 |
