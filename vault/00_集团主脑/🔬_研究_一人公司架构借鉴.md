# 借鉴 OneManCompany 方案 · 墨麟OS v5.1

## 评估结论
OMC（248⭐）与墨麟OS定位高度一致（一人公司 Agent OS），但各有优势。
墨麟OS胜在：22 Worker精细化分工、飞书集成、双语言生态、治理体系
OMC胜在：可视化办公室 UI、人才市场、辅导机制、任务树视图
→ 不合并代码，吸收 5 个高价值模块

---

## 模块一：像素风办公室 · 管理看板（优先级：P1）

OMC 最好用的功能：打开浏览器就能看到 AI 员工在工位上干活。

墨麟OS现状：管理全靠飞书消息+日志，没有整体感。

### 吸收方案
在现有 molib/dashboard.py 基础上，增加一个轻量 Web 看板：

```
python -m molib dashboard web --port 6789
```

页面内容：
- 22名 Worker 以"工位卡片"展示：姓名、当前状态（工作中/待命/离线）、最近产出
- 状态颜色：绿=正常、黄=告警、红=失败、灰=未部署
- 点击工位卡片 → 飞书聊天记录摘要 / 今日 KPI

实现方式：
- 后端：Flask（已有，MiroFish 也用的 Flask）
- 前端：单 HTML 文件 + vanilla JS（参考 OMC index.html 设计思路）
- 数据源：relay/ 目录各 Worker 的 JSON 文件
- 像素风：可选，用 CSS 像素字体模拟即可

### 工作量：2-3天
### 收益：大幅提升管理体验

## 模块二：1对1辅导 · 员工记忆进化（优先级：P2）

OMC 最强机制：CEO 可以坐下来"辅导"一个 AI 员工，教过的经验永久生效。

墨麟OS现状：self-learning-loop 反射协议和 Dream 蒸馏是类似思路，
但缺少"定向辅导"——针对特定 Worker 的个性化经验注入。

### 吸收方案
新增 molib/coach/ 模块：

```
python -m molib coach --agent content_writer --lesson "小红书的封面标题不要超过15个字"
```

- --agent：指定目标 Worker
- --lesson：辅导内容（自然语言）
- 系统自动将辅导内容包装为 SOP 片段，注入该 Worker 的 prompt
- 辅导记入该 Worker 的"成长档案"（SQLite），下次启动自动加载

### 工作量：1天
### 收益：解决"同一个错误反复犯"问题

---

## 模块三：人才市场 · 一键安装 Worker（优先级：P2）

OMC 的 Talent Market 让用户说"我需要一个设计师"就能从社区市场雇佣。

墨麟OS现状：skill-store 已经有基础，但只有本地技能安装，
没有社区市场，也没有"自然语言→自动匹配 Worker"流程。

### 吸收方案
扩展 molib/skill_store/ 为 skill_market/：

```
python -m molib market search "小红书内容运营"
python -m molib market install --name xiaohongshu-writer
python -m molib market publish ./my-worker  # 发布自己的Worker到市场
```

后端：
- 社区市场 URL（指向一个 GitHub org 或 HuggingFace repo）
- 每个 Worker 一个目录，包含 SKILL.md + template + config
- 安装流程：下载 → 校验 → 注册到 Hermes → 通知

### 工作量：2天
### 收益：降低"招人"门槛

## 模块四：绩效考核 · Agent 质检报告（优先级：P3）

OMC 有季度考核、PIP、甚至开除 AI 员工。

墨麟OS现状：质检靠 content_writer 的合规评分（68/100），
但没有系统化的"员工绩效评估"。

### 吸收方案
新增 molib/performance/ 模块：

```
python -m molib perf review --agent content_writer --period weekly
```

评估维度：
- 产出质量（合规评分 / 用户反馈）
- 任务完成率（cron 执行成功率）
- 成本效率（API token 消耗 vs 产出价值）
- 改进方向（基于 coach 记录的辅导历史）

输出：结构化 JSON 报告，存入 relay/performance/

### 工作量：1天
### 收益：让"开除/优化"决策有数据支撑

---

## 模块五：任务树可视化（优先级：P3）

OMC 用 G6 图引擎展示任务分解树。

墨麟OS现状：plan decompose 已经能输出结构化任务，
但只有 JSON，没有树状图。

### 吸收方案
给 `python -m molib plan visualize --plan-id xxx` 加个终端 ASCII 树输出，
再加个简易 HTML 树图（参考 OMC task-tree-g6.js 的思路）。

### 工作量：0.5天
### 收益：规划和进度一目了然
