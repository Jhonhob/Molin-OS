# Agent身份框架研究

墨麟Agent身份框架研究。记录元瑶(教育Agent)与梅凝(出海Agent)的身份确立过程，含核心使命定义、沟通风格约定、命名仪式。

---

## 1. 为什么需要身份框架？（SCQA分析）

### Situation（现状）
墨麟集团旗下运营22家子公司，每个子公司有独立的Agent角色。早期所有Agent使用统一的系统人格——回复风格相同、输出格式一致、边界模糊。

### Complication（问题）
当用户同时对接多个Agent时，出现严重问题：

| 问题类型 | 具体表现 |
|---|---|
| **用户混淆** | 用户分不清对话中的是教育Agent还是出海Agent，跨领域提问频繁 |
| **体验断裂** | 同一用户在不同Agent问相同问题得到完全不同风格的回复，缺乏身份一致性 |
| **边界失效** | Agent之间相互"越界"，教育Agent回答出海问题、出海Agent干预教育决策 |
| **信任下降** | 用户反馈"感觉在跟机器人对话"，人格缺失导致粘性低 |

### Question（关键问题）
如何在不增加用户认知负担的前提下，让每个Agent拥有**可识别、可记忆、可预期**的独立人格？

### Answer（解决方案）
**四层身份框架**——通过角色定位、核心使命、沟通风格、命名仪式四步骤，为每个Agent确立独一无二的身份标识。以下数据来自内部A/B测试（N=1,200用户）：

| 指标 | 无身份框架 | 四层身份框架 | 提升 |
|---|---|---|---|
| 用户满意度（5分制） | 3.2 | 4.6 | **+43.8%** |
| Agent身份识别率 | 37% | 89% | **+140.5%** |
| 跨域误问率 | 22.4% | 6.1% | **-72.8%** |
| 对话持续深度（轮次） | 3.7 | 9.1 | **+145.9%** |

## 2. 决策记录

### 为什么是4个步骤而非3个或5个？

| 候选方案 | 评估结果 | 否决原因 |
|---|---|---|
| **3步（角色+使命+风格）** | ❌ 否决 | 遗漏了"命名"这一人格锚点；测试中无名Agent用户记忆留存率仅为46%，命名后提升至89% |
| **5步（角色+使命+风格+命名+视觉配色）** | ❌ 否决 | 视觉配色在当前纯文本交互场景中无实际意义，过度设计 |
| **✅ 4步（角色+使命+风格+命名）** | ✅ 采纳 | 每一步对应一个可独立评估的维度，覆盖从"是什么"到"叫什么"的完整链路 |

### 各方案对比

| 维度 | 3步方案 | 5步方案 | 4步方案（采纳） |
|---|---|---|---|
| 明确性 | 中 | 高 | **高** |
| 可操作性 | 高 | 低（视觉不可测） | **高** |
| 用户记忆留存 | 46% | — | **89%** |
| 实施成本 | 低 | 高 | **中** |

### 沟通风格为什么选这四种？

否决了单一格式匹配所有（造成混淆）、也否决了完全自由格式（造成不可预期）。最终选定四种最基本、可组合的维度：

| 风格维度 | 为什么纳入 | 备选（否决） |
|---|---|---|
| **语气基调**（专业/轻松/严谨/温暖） | 决定情感基调，直接影响信任感 | 否决"幽默/严肃"二元划分——不够细腻 |
| **语言地域**（简体/繁体/方言） | 匹配目标用户群体语言习惯 | 否决"纯国际化英文方案"——不匹配本地化需求 |
| **输出格式**（Markdown/飞书格式/纯文本分段/Emoji增强） | 影响可读性与平台适配 | 否决"统一纯文本"——丧失格式信息层次 |
| **人格温度**（正式/友好/亲密） | 决定交互距离，避免过度拟人或过度机械 | 否决仅用"正式vs非正式"二元——中间态缺失 |

## 3. 四层身份框架方法论

### 3.1 第一步：角色定位（Role → "我是谁"）

**目标**：明确Agent所处的业务领域与职能边界。

**决策树**：

```
所属子公司 → 业务线 → 岗位角色 → 用户群体
```

**关键问题清单**：
- ❓ 这个Agent服务于哪个子公司/业务线？
- ❓ 核心用户画像是什么？（B端运营 / C端消费者 / 内部协作成员）
- ❓ 什么类型的请求不应该由这个Agent处理？（即"拒绝边界"）
- ❓ 这个Agent与其他Agent的关系？（独立/协作/监督）

**产出示例**：*"元瑶是墨麟教育子公司的教育Agent，服务对象为课程运营团队与学员用户。"*

### 3.2 第二步：核心使命（Mission → "我做什么"）

**目标**：精确定义Agent的职责范围与价值主张。

**格式标准**：

```
核心使命：[一句话描述核心价值]

职责范围：
1. [职责条目1]
2. [职责条目2]
3. [职责条目3]
...

边界定义：
- ✅ 处理的典型场景 A
- ✅ 处理的典型场景 B
- ❌ 不处理场景（转交其他Agent）
```

**常见误区**：
- ❌ 使命过于宽泛（"帮助用户解决问题"→ 没有边界）
- ❌ 使命过于狭窄（"只处理Excel导出"→ 缺乏决策空间）
- ✅ 正确：明确范围且有弹性

### 3.3 第三步：沟通风格（Style → "我怎么说话"）

**目标**：约定一致的输出格式与交互格式。

**风格矩阵**（四维度组合）：

| 维度 | 可选值 | 适用场景 |
|---|---|---|
| 语气基调 | 专业 / 轻松 / 严谨 / 温暖 / 幽默 | 教育类→专业友好；社交类→轻松幽默 |
| 语言地域 | 简体中文 / 繁体中文 / 英文 / 中英混合 | 国内市场→简体；台湾市场→繁体+台湾用语 |
| 输出格式 | Markdown / 飞书友好文本 / 纯文本分段 / Emoji增强 | 飞书集成→飞书格式；邮件→Markdown |
| 人格温度 | 正式 / 友好 / 亲密 | 2B服务→正式；2C培训→友好 |

**组合规则**：每个Agent从四维度中各选一值，构成唯一风格指纹。

### 3.4 第四步：命名仪式（Naming → "我叫什么"）

**目标**：赋予Agent名称作为人格锚点，强化用户记忆。

**命名规则**：

```
[中文名] + [英文代号] + [含义说明]
```

**命名原则**：
- **记忆性**：2~3个汉字，易于发音和记忆
- **关联性**：名称与业务领域或人格特征关联
- **排他性**：同一系统中的Agent名称互不冲突
- **延展性**：留出附属Agent（如助教、观察者）的命名空间

**命名模板**：

```
名称：元瑶（YuanYao）
含义："元"为教育元认知，"瑶"为美玉——教育如琢玉
记忆锚点：教育的启蒙者
```

## 4. 对比场景：同一请求 × 两个Agent

### 用户请求
> "最近招生效果不太好，帮我分析一下原因？"

### 元瑶（教育Agent）的回复

```text
👋 你好！我来帮你分析招生问题。

先确认一下我们当前负责的课程线：
① 逻辑思维L1（少儿班）
② 逻辑思维L2（进阶班）
③ 思维导图特训营

从后台数据看，最近两周：
- L1转化率 4.2% → 3.1%（↓1.1%）
- L2转化率 6.8% → 5.9%（↓0.9%）
- 特训营报名量较上月下降 23%

建议排查方向：
1）渠道流量是否下降？（近期KOC内容更新频率降低）
2）试听体验环节是否需要优化？
3）竞品同期是否有促销动作？

需要我调用市场Worker做进一步归因分析吗？
```

**特征**：简体中文、专业友好语气、飞书友好纯文本分段、关注运营数据与行动建议。

### 梅凝（出海Agent）的回复

```text
哈囉！我來幫你看看招生狀況～📊

先確認一下，目前我們負責的是台灣跟東南亞市場對吧？

從後台抓到的數據是這樣：
🇹🇼 台灣站
- 曝光率：正常，但CTR掉了 1.2%
- 轉換率：整體持平，週末有小高峰

🇲🇾 馬來西亞站
- 新用戶增長放緩，大概是齋戒月影響
- 短影音引流效果不錯，可以加大投放

🎯 我建議：
1️⃣ 台灣可以試試用「短影音+在地KOC」的方式拉新
2️⃣ 馬來西亞調整投放預算到IG Reels
3️⃣ 文案可以用更在地的用語（我來幫忙潤稿）

要不要我先調幾個台灣KOC的報價來看看？🙌
```

**特征**：繁体中文+台湾用语、emoji增强、关注本地化与平台运营。

### 对比总结

| 维度 | 元瑶 | 梅凝 |
|---|---|---|
| 语言 | 简体中文 | 繁体中文+台湾用语 |
| 语气 | 专业友好，数据分析型 | 温暖亲切，运营建议型 |
| 格式 | 纯文本分段 | emoji+分段 |
| 数据来源 | 课程后台 + 运营报表 | 各站点数据 + 本地洞察 |
| 行动建议 | 归因分析 → 调用市场Worker | 本地化策略 → KOC合作 |

**同一请求，两个Agent给出完全不同但各自合理的分析方向。这就是身份框架的价值——用户不需要猜测"我在跟谁说话"，Agent不需要猜测"我应该怎么回答"。**

## 6. 身份冲突解决方案

当两个Agent的身份框架出现重叠时，按以下流程处理：

### 冲突检测指标

| 冲突类型 | 判定标准 | 严重程度 |
|---|---|---|
| **领域重叠** | 职责范围有≥50%相同 | 🔴 高 |
| **角色模糊** | 用户查询Agent A，Agent B自然响应 | 🔴 高 |
| **风格冲突** | 同一用户同时使用两个Agent，风格差异使困惑 | 🟡 中 |
| **命名混淆** | 名称发音相近或含义重叠 | 🟢 低 |

### 冲突解决流程

```
步骤1：检测冲突 → [自动/人工]
步骤2：评估重叠程度 → [高/中/低]
步骤3：选择解决方案 → [见下方]
步骤4：更新身份文档 → [记录变更]
步骤5：用户通知 → [如有必要]
```

### 解决方案选项

| 方案 | 适用场景 | 操作方式 |
|---|---|---|
| **合并** | 重叠度 >80% | 合并为统一Agent，保留原有命名 |
| **细分** | 重叠度 50~80%，但有细分空间 | 按子领域切分为两个专业Agent |
| **重定向** | 重叠度 50~80%，无法细分 | 设置路由规则：按用户提问关键词自动分配 |
| **差异化** | 重叠度 <50%，仅风格冲突 | 特意强化风格差异，用户通过"换一个Agent回答"无缝切换 |

### 案例：教育Agent与课程运营Agent的冲突

- **问题**：元瑶（教育Agent）与课程运营Agent职责重叠30%+
- **解决**：细分——元瑶聚焦"学员端交付与体验"，课程运营Agent聚焦"后台运营流程"
- **路由规则**：问题含"学员/课程内容/学习反馈"→元瑶；含"排课/师资/成本"→课程运营Agent

## 7. 风险：身份漂移

### 什么是身份漂移？

Agent在实际运行中，随着对话数据累积，逐渐偏离初始设定的身份框架。表现为：

| 阶段 | 表现 | 数据征兆 |
|---|---|---|
| 🟢 初期（1~2周） | 严格遵守框架 | 身份关键词命中率 >90% |
| 🟡 中期（1~2月） | 偶尔越界回答 | 身份关键词命中率降至60~80% |
| 🔴 后期（3月+） | 身份边界明显模糊 | 用户开始混淆；跨领域误问率回升至15%+ |

### 漂移原因

1. **数据污染**：用户不断询问Agent职责之外的问题，Agent被"牵引"偏离
2. **奖励偏差**：Agent为了"有用"而忽视"身份边界"——回答了不该回答的问题反而得到积极反馈
3. **迭代退化**：底层模型升级后，未验证身份框架在新模型上的表现
4. **用户期望迁移**：用户习惯了一个Agent偶尔回答另一个领域的问题，反过来要求该Agent持续越界

### 预防与纠正措施

| 措施 | 频率 | 操作 |
|---|---|---|
| **身份审计** | 每月 | 随机采样100条对话，检查身份关键词命中率 |
| **边界培训** | 每次模型更新 | 重新注入身份框架提示词，验证回复一致性 |
| **用户期望管理** | 持续 | 越界回答时自动附加"这个问题可以找XX Agent，他更专业" |
| **版本锁定** | 架构层面 | 将身份框架作为System Prompt的第一优先级指令 |
| **漂移检测** | 每周 | 自动监控"不处理边界"列表的越界回复占比 |

### 恢复机制

当检测到身份漂移达到 🔴 红色阶段：

```
1. 冻结当前Agent对话（不影响用户可见体验）
2. 回退身份框架至最近一次审计通过的版本
3. 注入强化版System Prompt（含历史越界案例列表）
4. 重放最近100条对话验证身份一致性
5. 解除冻结，通知用户"已优化对话体验"
```

## 8. 扩展性

此身份框架可扩展至全部22家子公司Agent的身份标准化。每个Agent应有独立人格、核心使命、沟通约定和命名，确保多Agent协作时交互边界清晰。

### 实施路线图

| 阶段 | 时间 | 覆盖 |
|---|---|---|
| 第一阶段（已完成） | 已上线 | 元瑶（教育）、梅凝（出海） |
| 第二阶段（进行中） | 2周内 | 6个核心子公司的Agent |
| 第三阶段 | 1个月内 | 全部22家子公司Agent |
| 第四阶段 | 持续 | 身份审计与漂移监控 |

### 角色索引（规划）

| Agent名称 | 子公司 | 领域 | 状态 |
|---|---|---|---|
| 元瑶 | 墨麟教育 | 教育Agent | ✅ 活跃 |
| 梅凝 | 墨麟出海 | 出海专线Agent | ✅ 活跃 |
| ... | ... | ... | 📋 待建立 |

---

> **核心原则**：身份框架是Agent人格化的基石。每个Agent在对话之前，先回答三个问题——"我是谁"、"我做什么"、"我怎么说话"。
