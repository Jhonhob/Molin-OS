# 全景模型库与Agent同步协议

本规范是墨麟OS知识沉淀与自动化工作的最高纲领。Hermes Agent在向Obsidian同步或更新任何方案、报告、计划时，必须强制映射至少一个核心模型，确保单篇文档具有极高的逻辑密度与结构化可读性。

---

## 一、全景思维与分析模型矩阵

### 1. 认知、表达与逻辑底座

金字塔原理：任何笔记的最高结构准则，结论先行、以上统下、归类分组、逻辑递进。

MECE原则：在拆解业务、渠道、指标、功能、风险时，各要素间绝不允许重叠，且不漏掉关键维度。

SCQA模型：所有方案、报告、测试文件的背景模块强制套用情境(Situation)→冲突(Complication)→疑问(Question)→解答(Answer)结构。

DIKW架构：记忆分层标准。原始Data/Info留存Agent本地向量库，加工后的Knowledge/Wisdom写入Obsidian。

5W1H × SMART：任务描述与指标设定的铁律，包含Who/What/When/Where/Why/How，目标必须具体、可衡量、可达到、相关、有明确截止期限。

PDCA循环：长青文档的滚动迭代标准，变更必须记录于文档末尾的修订日志。

### 2. 战略与商业环境分析模型

TAM/SAM/SOM测算模型：总潜在市场规模、可服务市场规模、可获取市场规模，精准界定赛道规模与可吃下的份额。

波特五力模型：评估赛道竞争激烈度，涵盖供应商议价能力、购买者议价能力、新进入者威胁、替代品威胁、同业竞争。

PESTEL分析模型：从政治、经济、社会、技术、环境、法律六大宏观维度研判行业政策与AI趋势。

SWOT分析：评估项目的优势、劣势、机会、威胁，推导出具体的交叉执行战略(SO/WO/ST/WT)。

行业集中度指标CRn：衡量竞争格局，如前五大头部品牌市场占有率变化。

安索夫矩阵：明确增长路径，涵盖市场渗透、市场开发、产品开发、多元化。

### 3. 用户增长与全渠道获客模型

AARRR/RARRA模型(教育改良版)：获客→激活试听→完课留存→续费LTV→转介绍，AI时代更强调以留存(RARRA)为核心。

增长飞轮与增长循环：用输入→动作→输出→新输入的闭环替代传统线性漏斗。

内容营销三层漏斗：ToFu广撒网建立认知、MoFu激发意向获取线索、BoFu精准转化。

全渠道归因模型：明确获客功劳归属，含首次触点、末次触点、线性多触点归因。

RICE/ICE优先级评估模型：得分 = (触达量 × 影响力 × 信心) / 投入成本。

### 4. 用户心理与行为干预模型

福格行为模型B=MAP：用户行为未发生时，必须从动机(M)、能力门槛(A)、触发器(P)三个维度全面诊断。

上瘾模型Hook Model：打造高黏性学习习惯的四步循环——触发、行动、多变酬赏、投入。

用户旅程地图：梳理用户在触达、试听、付费、上课、续费等阶段的动作、痛点及心理情绪曲线。

布鲁姆认知层次分类：将思维能力从低到高拆解为记忆、理解、应用、分析、评估、创造。

### 5. 数据、算法与技术验证模型

HADI循环：增长实验标准——提出假设、采取行动、采集数据、提取洞察。

同期群分析Cohort Analysis：将用户按特定时间批次隔离观察其生命周期的行为衰减。

BKT贝叶斯知识追踪算法：诊断Agent的算法底座，连续推算对每个知识点的掌握概率。

FSRS自适应复习算法：教练Agent的排期模型，动态计算最优复习间隔。

## 三、Agent笔记同步与记录执行协议

### 3.1 自动分类规范

Agent接收信息后必须进行语义识别，精准投放至对应纯中文目录：

技术架构、接口规范、安全备份、底层埋点规范 → 归入系统层/

具体项目执行方案、测试设计、产品文档、业务SOP → 归入业务层/

渠道大盘策略、营销获客数据、商业计划书、ROI分析 → 归入运营层/

学术论文内化、记忆科学研究、垂直行业白皮书 → 归入知识库/

### 3.2 格式重构协议

强制生成YAML Front Matter，包含title/status/last_updated/agent_sync/frameworks_applied。

强制在正文顶部输出核心摘要，用精炼商业语言概括全文。

标题层级严格匹配金字塔原理，禁用冗余叙述。

列表项必须执行MECE校验，自动完成逻辑合并与优化。

### 3.3 长青文档更新与合并协议

禁止版本碎片化：更新既有策略时，必须检索既有同名主文档。

执行覆写与增量合并：将新数据融合进原文档对应章节，替换陈旧数据。

强制更新修订日志：在文档最末尾追加变动核心动作及原因。

### 3.4 触发限制

拒绝流水账。严禁将日常调试日志、临时情绪表达、未总结的会话逐字稿同步至Obsidian。只有当内容进化为具有长期指导意义的正式文件时，方可激活本同步协议。

### 3.5 Agent同步前合规检查清单

Agent在向Obsidian写入或更新任何笔记前，必须逐一通过以下合规检查项。任一检查未通过则中止同步并生成整改反馈。

| # | 检查项 | 强制 | 通过条件 | 失败处理 |
|---|--------|------|---------|---------|
| C1 | 模型映射完整性 | ✅ | `frameworks_applied` 中至少列出1个核心模型；推荐≥2个 | 提示"请指定至少一个全景模型" |
| C2 | SCQA开头完整性 | ✅ | 正文前200字内出现S(情境)或C(冲突)或明确的摘要结构 | 自动插入SCQA框架占位符 |
| C3 | YAML Front Matter完整性 | ✅ | 包含title/status/last_updated/agent_sync/frameworks_applied五项 | 拒绝写入，补全后重试 |
| C4 | 目录投放正确性 | ✅ | 路径归属系统层/业务层/运营层/知识库之一 | 按语义自动重分类 |
| C5 | 标题层级合规 | ✅ | 标题编号不跳级（如无H1直接H3），格式为 `## → ### → ####` | 自动降级/升级修复 |
| C6 | MECE逻辑校验 | ⚡ 严格建议 | 列表项中无重叠条目 | 输出建议合并项 |
| C7 | 修订日志更新 | ✅ | 若更新已有文档，末尾必须有本次变更记录 | 追加占位日志，强制更新 |
| C8 | 内容去流水账 | ✅ | 非日常日志、非临时情绪、非原始逐字稿 | 触发则拒绝同步 |
| C9 | 核心摘要存在 | ✅ | 正文顶部存在一段≥30字的摘要 | 自动生成摘要 |
| C10 | DIKW层级标注 | ⚡ 推荐 | Data/Info层级的笔记标注 `draft: true` | 输出建议标注 |

**合规执行伪代码**：
```python
def pre_sync_checklist(note: Note) -> SyncResult:
    checks = {
        "C1": len(note.frameworks) >= 1,
        "C2": has_scqa_prefix(note.body),
        "C3": has_valid_front_matter(note.front_matter),
        "C4": note.path in ALLOWED_DIRECTORIES,
        "C5": is_heading_level_valid(note.body),
        "C7": has_revision_log(note.body) if note.is_update else True,
        "C8": not is_waterflow(note.body),
        "C9": len(get_summary(note.body)) >= 30,
    }
    failed = [k for k, v in checks.items() if not v]
    if failed:
        return SyncResult(approved=False, failed_checks=failed,
                          fix_suggestions=generate_fixes(failed))
    return SyncResult(approved=True)
```

## 五、真实实施案例：SCQA+金字塔重构战略笔记

### 5.1 原始输入（Agent收到的碎片化信息）

```
最近调研了几个竞品，A公司用了AI批改作文，B公司推了1对1口语陪练。
我们自己的产品在二季度完课率掉了5个点，是不是该加个AI功能？
要不先做AI作文批改，毕竟技术团队刚招了两名NLP工程师。
```

### 5.2 Agent处理后输出（结构化笔记）

```yaml
---
title: Q2完课率修复方案：AI作文批改功能立项建议
status: 草稿
last_updated: 2026-05-19
agent_sync: true
frameworks_applied:
  - 金字塔原理
  - SCQA
  - MECE
  - PDCA
---
```

**核心摘要**：Q2完课率同比下降5pp，经竞品对标与用户行为诊断，建议优先投入AI作文批改功能，预计上线后完课率提升3-4pp，ROI约1:4.2。

**S — 情境 (Situation)**
- 当前产品为K12英语在线陪练，Q1完课率82%，Q2下降至77%
- 技术团队扩充完毕，具备NLP工程能力

**C — 冲突 (Complication)**
- 竞品A上线AI批改后完课率升至89%；竞品B口语陪练付费转化率提升22%
- 不跟进则暑期获客处于劣势

**Q — 问题 (Question)**
- 投入有限资源下，应优先开发AI作文批改还是AI口语陪练？

**A — 答案 (Answer)**
- **推荐方案**：优先AI作文批改（理由见下文）

### 5.3 MECE拆解：方案对比

| 评估维度 | 方案A：AI作文批改 | 方案B：AI口语陪练 |
|----------|-------------------|-------------------|
| 技术成熟度 | 团队已有NLP经验，2周可上线MVP | 需语音识别+语音合成，预计6周 |
| 用户需求强度 | 完课率下降主因：作业批改反馈慢（NPS调研第1痛点） | 需求存在，但非Q2核心卡点 |
| 投入成本 | 2人×2周 | 3人×6周 |
| 预期ROI | 完课率↑3-4pp，收入↑约¥60W/月 | 转化率↑5%，收入↑约¥35W/月 |

| 周期 | 动作 |
|------|------|
| P(计划) | 2026-06-01前完成MVP开发，灰度5%用户 |
| D(执行) | 2026-06-07上线，灰度用户完课率实时看板 |
| C(检查) | 2026-06-14对比灰度/对照组完课率差异 |

## 六、BKT+FSRS协作机制：诊断Agent与教练Agent的算法流程

### 6.1 角色定义

| 角色 | Agent类型 | 核心模型 | 职责 |
|------|-----------|---------|------|
| 诊断Agent | 分析型 | BKT贝叶斯知识追踪 | 评估学生对每个知识点的掌握概率，定位薄弱点 |
| 教练Agent | 排期型 | FSRS自适应复习算法 | 为每个已标注薄弱点计算最优复习时间窗口 |

### 6.2 协同算法流程

```

│  └──────────────┘    └──────────────┘    └───────┬───────────┘  │
│                                                   │              │
```

### 6.3 BKT核心更新公式

```
初始化：P(L_0) = 初始掌握概率（默认0.15）
每步更新：
  P(L_n | correct) = P(L_n) * (1 - P(slip)) /
                     [P(L_n) * (1 - P(slip)) + (1 - P(L_n)) * P(guess)]

  P(L_n | wrong) = P(L_n) * P(slip) /
                   [P(L_n) * P(slip) + (1 - P(L_n)) * (1 - P(guess))]

  学习后（有教学干预）：P(L_{n+1}) = P(L_n | evidence) + (1 - P(L_n | evidence)) * P(transit)
  其中：P(transit) = 经过一次学习从"不会"到"会"的转移概率
```

### 6.4 FSRS Recall概率公式

```
R(t) = 2^(-t / S)  其中 S 为稳定性(以天为单位)
t = 距上次复习的天数
复习后新的稳定性 = S * (e^(r_factor) - 1)   // 复习成功
复习后新的稳定性 = S * (e^(-d_factor))       // 复习失败（遗忘）
```

### 6.5 协作触发条件

| 条件 | 诊断Agent动作 | 教练Agent动作 |
|------|-------------|-------------|
| P(L) < 0.4 | 标记为"红色薄弱点"，触发立即干预 | 安排当天+明天连续复习 |
| 0.4 ≤ P(L) < 0.6 | 标记为"需关注点" | 按FSRS计算间隔推送 |
| 0.6 ≤ P(L) < 0.8 | 标记为"巩固中" | 延长复习间隔至3-7天 |
| P(L) ≥ 0.8 | 移除薄弱点标记 | 转入月度抽查队列 |

## 七、跨模型组合指南

### 7.1 推荐组合链

| 序号 | 组合链 | 适用场景 | 为什么这样串联 |
|------|--------|---------|--------------|
| 1 | PESTEL → SWOT → TAM-SAM-SOM | 市场进入策略（新品立项） | 宏观扫描→自身定位→量化市场，数据流不中断 |
| 2 | SCQA → 用户旅程地图 → Hook Model | 产品体验优化 | 先定义「问题在哪」→「卡在哪一步」→「怎么让人上瘾」 |
| 3 | AARRR → 同期群分析 → PDCA | 增长复盘与改进 | 全景看漏斗→分群看趋势→迭代闭环 |
| 4 | 5W1H×SMART → 金字塔原理 → MECE | 目标拆解与OKR制定 | 明确目标→顶层结论→无重叠分解 |
| 5 | 波特五力 → 安索夫矩阵 → RICE评分 | 战略方向选择与优先级 | 竞争分析→增长路径→项目排优先级 |
| 6 | HADI → 福格B=MAP → 同期群分析 | 增长实验全流程 | 提出假设→诊断行为→分群验证 |

### 7.2 组合使用铁则

1. **模型不要堆砌**：单篇文档建议2-4个模型，超过4个需在摘要说明为什么都需要
2. **数据流必须连贯**：前一个模型的输出是后一个模型的输入（如PESTEL的威胁→SWOT的T）
3. **避免冲突模型**：DIKW作为分层标注，不与任何模型冲突，可追加；SWOT与安索夫矩阵有交叉，建议二选一或明确分节使用
4. **标记主模型与辅模型**：在文档 `frameworks_applied` 中靠前的模型为主模型，决定文档的一级结构

## 八、模型误用风险与纠偏机制

### 8.1 常见误用模式

| 误用类型 | 典型表现 | 后果 | 检测方式 |
|---------|---------|------|---------|
| 模型滥用堆砌 | 一篇笔记同时使用6个以上模型 | 结构混乱，核心信息被稀释 | YAML检查：`frameworks_applied` > 4 则触发预警 |
| SCQA头重脚轻 | S/C占全文80%，A只有一行 | 有诊断无方案，实用性为0 | 检测A段字数，需≥S+C总和的30% |
| MECE漏项 | 拆解时遗漏关键维度（如只写优势不写劣势） | 决策偏见，盲区扩大 | 是否成对出现（SWOT四象限都有数据、正反对比项均有） |
| PDCA无闭环 | 只有P(计划)和D(执行)，无C(检查)A(改进) | 文档成为一次性的"僵尸文档" | C段和A段必须非空 |
| 金字塔跳跃 | 二级结论直接跳到四级细节，缺失三级 | 逻辑断层，读者无法跟住论证链 | 标题层级连续性检测 |
| BKT参数随意 | P(slip)=0.5,P(guess)=0.5（纯随机） | 诊断结果无意义，等于猜硬币 | 参数合理性校验：P(slip)≤0.3,P(guess)≤0.3 |

### 8.2 自动纠偏流程

```
发现误用 ─→ 输出误用诊断报告 ─→ 触发自动修复
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
          ┌─────────────────┐            ┌────────────────────┐
          │ 可自动修复       │            │ 需人工介入          │
          │ - 精简模型堆砌    │            │ - 补全MECE漏项     │
          │ - 调整SCQA篇幅    │            │ - 校准BKT参数     │
          │ - 修复标题层级    │            │ - 补充PDCA闭环     │
          │ - 插入A段占位符   │            └────────┬───────────┘
          └────────┬────────┘                     │
                   ▼                              ▼
          ┌──────────────────────────────────────────┐
          │ 输出修正版本（标注"[Auto-fixed]"）        │
          │ 记录修正动作至修订日志                     │
          │ 由用户确认后方可正式同步                    │
          └──────────────────────────────────────────┘
```

### 8.3 误用自检Scorecard

Agent在每次同步前自动计算模型误用风险分：

| 维度 | 扣分规则 | 满分 |
|------|---------|------|
| 模型数量合理性 | 1-4个不扣分，5个-3分，6个+ -5分 | 10 |
| SCQA回答充分性 | A字数/S字数 < 30% -4分 | 10 |
| MECE完备性 | 发现漏项 -3分/项 | 10 |
| PDCA完整性 | 缺C或缺A -5分 | 10 |
| 标题层级连续性 | 发现跳级 -2分/次 | 10 |
| **总分** | — | **50** |

> 风险等级：≥40分低风险→直接同步；30-39分中风险→自动修复后同步；<30分高风险→冻结，需人工审核。
