## SCQA：为什么财务透明是当前最紧迫的问题

**Situation（情境）**：墨算运营层已具备3条业务线（内容线、教育线、副业线）和22个Agent节点，日API消耗量稳步增长，但财务数据采集仅覆盖1/22的Agent（content_writer）。

**Complication（挑战）**：没有完整的成本数据，增长决策相当于盲人摸象——无法判断哪个Agent/模型最烧钱、哪个业务线ROI最高、预算是否真正够用。当前覆盖率仅4.5%，意味着95.5%的成本处于黑箱状态。根据抽样外推，实际日成本可能在5-10元区间（账面1.66元的3-6倍），月实际成本可能已达150-300元但仍远低于1,360元预算——问题不是钱不够，而是看不见。

**Question（问题）**：如何在不增加人力负担的前提下，将KPI覆盖率从4.5%提升至100%，让每一笔API调用都有归属和成本归因？

**Answer（答案）**：分阶段推进全Agent KPI标准化上报，每阶段设定明确的覆盖率里程碑和置信度验证，同步建立成本异常检测机制。

### 决策记录：为什么 content_writer 是唯一上报的Agent？

- **2026-04初期约定**：运营层初建时约定所有Agent上报JSON KPI，但未强制化。
- **技术原因**：content_writer 最先内嵌 KPI 上报模块；其他 Agent 依赖推理/副业线工作流，上报尚未集成。
- **资源原因**：未设立统一KPI采集Agent，上报依赖各Agent维护者手动配置。
- **预算阈值1,360元为何选定**：基于月均12-15元实际支出（估算）的约100倍安全边际设定。该阈值的推导逻辑是——假设全部22个Agent全量上线、模型使用Pro/Vision版本、日均Token消耗扩大10倍，月成本仍可控制在1,000元以内。预留360元作为突发峰值缓冲。**注意：该假设未经验证，随覆盖率提升可能需调整。**

## 成本驱动因子分析（Pareto原则）

根据当前单Agent数据及行业基准估算，22个Agent的潜在成本分布可能遵循80/20法则：

| 成本层级 | 预计Agent数量 | 预计成本占比 | 典型Agent类型 |
|----------|--------------|------------|--------------|
| 高消耗层 | 3-4个Agent | ~80%成本 | 含Vision推理的Agent（如图片分析、多模态生成）、深度推理Agent（O1/Pro级别推理） |
| 中消耗层 | 5-7个Agent | ~15%成本 | 标准DeepSeek Pro Agent（如教育线答题生成） |
| 低消耗层 | 10-14个Agent | ~5%成本 | Flash Agent、纯文本轻量Agent（如关键词提取、简单分类） |

### Token消耗预估（按Agent类型）

| Agent类型 | 日均Token估计 | 模型 | 日成本估计 |
|-----------|-------------|------|-----------|
| 纯文本内容生成 | 50K-100K | DeepSeek Flash | 1-3元 |
| 教育推理 | 100K-300K | DeepSeek Pro | 5-15元 |
| 多模态分析 | 50K-150K | Qwen-VL-Max | 10-30元 |
| 代码生成/审查 | 80K-200K | DeepSeek Pro/Flash | 4-12元 |

> ⚠️ 以上为理论估算。实际成本需等Agent KPI覆盖后确认。

## 情景推演：当KPI覆盖率提升时

### 当覆盖率达到 50%（约11个Agent上报）

| 推演结果 | 说明 |
|---------|------|
| 真实日成本揭露 | 大概率落在5-15元区间，而非账面1.66元 |
| 发现高成本Agent | 教育线推理Agent可能单日消耗3-8元，远超content_writer |
| 预算口径调整 | 月预算可能从当前估算的46元上调至150-450元 |
| Provider权重重构 | DeepSeek Pro和Qwen-VL-Max可能占据60-80%实际成本 |

### 当覆盖率达到 100%（全部22个Agent上报）

| 推演结果 | 说明 |
|---------|------|
| 完整成本画像 | 可生成每Agent每模型的精确成本周报 |
| 发现浪费Agent | 可能发现5-8个Agent月活<3次但持续拉取上下文（闲置成本） |
| 发现未授权调用 | 可能发现未被记录的Provider/Model组合 |
| 预算模型成熟 | 可用历史数据建立预算预测模型，误差<10% |
| 异常检测上线 | 阈值告警：单Agent日成本突然飙升>300%时触发 |

## 风险矩阵

### 风险1：实际成本5倍于账面，预算冲击

| 维度 | 详情 |
|------|------|
| 可能性 | **中**（40-50%） |
| 影响 | 月实际成本可能达200-400元，当前预算1,360元仍有余量，但需警惕累计增长 |
| 触发信号 | 单个Agent日成本>5元；周成本环比增长>100% |
| 缓解措施 | 每两周手动抽样2-3个未上报Agent的API日志做成本推算；设置预算缓冲区（预留20%余量） |

### 风险2：突发成本峰值

| 维度 | 详情 |
|------|------|
| 可能性 | **低**（15-25%） |
| 影响 | 某日成本超100元（如大批量Vision推理任务），单日超月预算7% |
| 触发信号 | Vision密集型任务同时涌入 |
| 缓解措施 | 在推理集群层面设置每日成本上限；Vision任务单独排队 |

### 风险3：数据质量问题——当前上报数据的可靠性

| 维度 | 详情 |
|------|------|
| 可信度 | content_writer的JSON KPI相对可信（程序自动上报，人为篡改概率低） |
| 潜在偏差 | Token计数可能因缓存命中减少（DeepSeek Flash缓存命中不计费，但KPI可能仍按原始Token报） |
| 缺失维度 | 无网络延迟成本、无模型切换成本、无上下文窗口利用率 |
| 置信区间（当前） | ±30-50%（因样本量太小，1个Agent无法代表整体） |
| 建议 | 在阶段一中至少采集3-5个Agent数据后才进行成本推论 |

## 核心结论

1. **当前最大的财务风险不是预算超支**（¥1,360/月预算对当前消耗极为充裕），**而是数据覆盖不足导致成本盲区**——95.5%的Agent成本不可见。
2. **KPI覆盖率提升路线图清晰可执行**：10周内分三阶段从4.5%覆盖到100%。
3. **收入管线存在但时间不确定**：首个收入预计在2026-Q3，当前应优先确保成本透明。
4. **建议下阶段优先事项**：①统一KPI上报模板 ②为教育线Agent嵌入上报 ③建立成本异常检测基线。
