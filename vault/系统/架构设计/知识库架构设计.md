## 一、核心问题诊断

| # | 问题 | 表现 |
|---|------|------|
| 1 | **分类名实不符** | System/README 说 6 类（带 emoji），实际 Agents/ 下只有 4 类 + 遗留  系统与配置，概念与执行脱节 |
| 2 | **时间戳文件爆炸** | 每天每 agent 产生 3 个 `2026-05-15_182501_银月传媒·任务执行...md`，3×5=15 个文件/天，月增 450 个 |
| 3 | **无质量过滤** | 文件内容 = 原始对话流水账 + 终端输出全文，没有提炼、没有结论先行 |
| 4 | **分类边界模糊** | "项目/" 同时包含决策（CloakServe集成）、进展（日常运维日志）、调研（创业调研日志） |
| 5 | **日报分散** | Daily/ 下 5 个 agent 各一个日报 + 根目录一个空 `2026-05-15.md`，无法一眼看全局 |

## 二、新体系总览

### 2.1 目录结构

```
Vault/
├── Agents/
│   ├── media/         ← 银月传媒（内容创作、社媒运营）
│   │   ├── 决策/      ← 不可逆的选择（技术选型、方向定稿）
│   │   ├── 知识/      ← 沉淀积累（研究、架构、思维模型）
│   │   ├── 流程/      ← 可执行步骤（SOP、配置、操作手册）
│   │   └── 成果/      ← 可交付物（报告、产出物、数据）
│   ├── global/        ← 梅凝出海（跨境电商、海外市场）
│   │   └── 同上 4 类
│   ├── edu/           ← 元瑶教育（课程设计、学习辅导）
│   │   └── 同上 4 类
│   ├── shared/        ← 玄骨中枢（运维、CRM、数据）
│   │   └── 同上 4 类
│   └── side/          ← 宋玉创业（副业探索、创业）
│       └── 同上 4 类
├── Daily/
│   └── <YYYY-MM-DD>.md      ← 唯一聚合日报，按 Agent 分区
├── System/                    ← 不变（架构、memory-map、agent 配置）
└── Archive/                   ← 旧结构迁移至此（只读，不更新）
```

### 2.2 4 分类的 MECE 定义

| 分类 | 定义 | 包含 | 不包含 | 例子 |
|------|------|------|--------|------|
| **决策** | 不可逆的、高代价的、一旦变更需要迁移的选择 | 技术选型、架构定稿、工具替换、战略方向 | 日常进展、调研笔记 | CloakServe 方案定稿、Shopify 结算选型 |
| **知识** | 经过提炼的学习成果，持续积累但不直接可执行 | 研究沉淀、架构理解、思维模型、竞品分析 | 操作步骤、配置参数 | SourceAdapter 架构、台湾市场洞察 |
| **流程** | 可以照着做的操作步骤，可版本化管理 | SOP、配置指南、检查清单、操作手册 | 单个决策、学习笔记 | 封面生成 SOP、Shopify 上架流程 |
| **成果** | 有时间属性的可交付物 | 报告、日报、产出物、数据、文章 | 操作步骤、研究笔记 | GitHubTrending 日报、百炼生图测试报告 |

**判断口诀**：
> 决定了就改不了 → **决策**  
> 学了用来参考 → **知识**  
> 照着做就完成 → **流程**  
> 产出给别人看 → **成果**

## 三、属性体系（Frontmatter 规范）

### 3.1 必填属性

```yaml
---
created: 2026-05-15          # 文件创建日期（必填）
updated: 2026-05-15          # 最后更新日期（必填）
agent: media                  # 所属 agent ID（必填，仅限：media/global/edu/shared/side）
category: 决策                 # 分类（必填，仅限：决策/知识/流程/成果）
status: 活跃                   # 状态（必填，仅限：活跃/冻结/归档）
confidence: 已验证             # 可信度（必填，仅限：已验证/待验证/假设）
importance:               # 重要程度（必填，仅限：//）
source: 实践                   # 来源（必填，仅限：自研/调研/实践/对话/外部）
tags: [tag1, tag2]            # 标签（必填，至少 1 个）
---
```

### 3.2 可选属性

```yaml
---
related: [[相关文件]]          # 关联笔记
deprecated_by: [[替代方案]]    # 被哪个新方案替代
version: 2                    # 流程/知识 的版本号
review_date: 2026-06-15       # 下次审查日期
---
```

### 3.3 属性值详解

**status（状态）**
| 值 | 含义 | 使用场景 |
|----|------|----------|
| 活跃 | 当前有效，持续更新 | 所有正在使用的文件 |
| 冻结 | 暂不更新，保留参考 | 季度报告、阶段性成果 |
| 归档 | 不再使用，仅历史查阅 | 被替代的方案、过期 SOP |

**confidence（可信度）**
| 值 | 含义 | 例子 |
|----|------|------|
| 已验证 | 自己实践验证过 | CloakServe 集成步骤（实际部署通过） |
| 待验证 | 基于研究/推理，尚未实践 | 某个 API 对接方案（调研了但没落地） |
| 假设 | 推测，需要实验验证 | 某个市场策略的猜测 |

**importance（重要程度）**
| 值 | 含义 | 例子 |
|----|------|------|
|  | 碎片参考，可有可无 | 某篇博文的链接 |
|  | 常规知识，日常使用 | SOP、常规架构 |
|  | 核心资产，不可丢失 | 身份定义、关键决策、核心架构 |

**source（来源）**
| 值 | 含义 |
|----|------|
| 自研 | 自己设计的方案 |
| 调研 | 研究外部资料所得 |
| 实践 | 操作/实验验证所得 |
| 对话 | 来自对话讨论 |
| 外部 | 转载/引用外部内容 |

**tags（标签词表 — 推荐使用）**
```
领域标签:   cloakserve / shopify / github / 社媒 / 课程设计 / 运维 / 创业
类型标签:   技术选型 / 架构设计 / 调研报告 / 日报 / SOP / 配置 / 复盘
行动标签:   进行中 / 待验证 / 已完结 / 需定期更新
```

### 3.4 文件名规范

```
规则：主题.md（不含时间戳、不含 agent 名、不含分类名）

 正确：CloakServe集成.md
 正确：封面生成SOP.md
 正确：台湾市场调研.md
❌ 错误：2026-05-15_182501_银月传媒·任务执行.md
❌ 错误：银月传媒_CloakServe集成.md（文件名含 agent 名，冗余）
❌ 错误：决策_CloakServe集成.md（文件名含分类，frontmatter 已有）
```

## 六、Living Document 操作规范

### 6.1 写入前问三个问题

```
Q1：这是结论还是流水账？
    → 只保留结论。原始对话记录 ≠ 笔记。
    → 禁止：直接粘贴终端输出、直接粘贴对话全文

Q2：30 天后还值得看吗？
    → 值得 → 写进对应的分类文件
    → 不值得 → 不写（对话记录保留在对话记录目录，30天后淘汰）

Q3：有这个主题的文件了吗？
    → 有 → 追加更新，不新建
    → 没有 → 创建，按命名规范
```

### 6.2 更新已有文件的流程

```
1. 用 read_file 读取现有文件
2. 在末尾追加新的 section（金字塔格式）
3. 更新 frontmatter 的 updated 日期
4. 如果发现旧内容已过时：用 patch 标记为 ~~删除线~~ 并注明替代链接
5. 从不删除旧内容（保留历史），但用 frontmatter status: 归档 标记
```

### 6.3 内容格式（金字塔原则）

每个 section 按此结构：

```markdown
## 主题名称（Time: 2026-05-15）

### 结论
一句核心结论。

### 理由
- 理由 1 — 事实支撑
- 理由 2 — 事实支撑

### 详情（可选）
仅当需要展开时才写。

### 下一步
- [ ] 行动项
```

### 6.4 对话记录目录的处理

Agents/*/对话记录/ 保留，但：

1. 只保留最近 7 天的文件（之前的压缩或删除）
2. 对话记录不写 frontmatter，不做链接，不参与知识体系
3. 有价值的决策/知识/流程/成果 → 提取到对应的 4 分类文件中
4. 对话记录本质是临时缓存，不是知识资产

## 九、设计原则总结

| 原则 | 说明 |
|------|------|
| **MECE 分类** | 4 类互斥穷尽：决策（不可逆）≠ 知识（可修正）≠ 流程（可执行）≠ 成果（可交付） |
| **金字塔原则** | 结论先行，以上统下，归类分组 |
| **单文件单主题** | 一个文件一个主题，不按时间分片 |
| **属性驱动** | 靠 frontmatter 检索，不靠目录路径 |
| **聚合 Daily** | 每日 5 个 agent 聚合到一份文件，链回详情 |
| **质量门禁** | 三个问题过滤：结论？30天价值？重复？ |
