## 第一章：分类判定树

### 1.1 四选一决策树

每次写入前，走这个流程：

```
内容来了
  │
  ├─ 这是一个不可逆的选择吗？
  │   （技术选型、架构定稿、工具替换、战略方向）
  │   → 决策/
  │
  ├─ 不，这是照着做就能完成的操作步骤？
  │   （SOP、配置、检查清单、操作手册）
  │   → 流程/
  │
  ├─ 不，这是学来的知识，不是操作步骤？
  │   （研究结果、架构理解、思维模型、竞品分析）
  │   → 知识/
  │
  └─ 不，这是有时间属性的产出物？
      （报告、日报、可交付物、数据）
      → 成果/
```

### 1.2 各 Agent 的典型内容（参考表）

| Agent      | 决策/                        | 知识/                   | 流程/                  | 成果/               |
| ---------- | -------------------------- | --------------------- | -------------------- | ----------------- |
| **media**  | 技术选型(CloakServe)、社媒策略、工具替换 | 内容创作模式、平台算法、视觉设计理论    | 封面生成SOP、发布流程、工具链配置   | 测试报告、封面产出、热点简报、日报 |
| **global** | 目标市场选择、Shopify方案、物流通道选型    | 跨境平台规则、本地文化洞察、竞争分析    | 上架流程、物流配置、市场调研SOP    | 市场分析报告、周报、数据      |
| **edu**    | 课程平台选型、教具技术栈、定价策略          | 教学理论、课程设计框架、学习路径研究    | 课程录制流程、学员跟进SOP       | 课程大纲、教学计划、学员报告    |
| **shared** | 基础设施选型、部署方案、系统架构变更         | 运维经验、拓扑理解、故障复盘、CRM方法论 | 部署SOP、备份脚本、监控配置、切换流程 | 系统巡检报告、趋势日报、健康检查  |

### 1.3 边界案例判定

| 模糊内容 | 判定逻辑 | 归类 |
|----------|---------|------|
| "对比了 A 和 B，选了 A" | 这是决策，不可逆 | 决策/ |
| "A 和 B 的区别如下" | 这是学习笔记，可修正 | 知识/ |
| "安装 A 的步骤：1.brew install" | 这是操作步骤 | 流程/ |
| "本周 A 的数据增长 20%" | 有时间属性，是产出 | 成果/ |
| "今天做了 A 和 B 两个调研" | 调研结果 → 知识；调研操作 → 流程 | 视内容比例 |

## 第二章：写入质量门禁

### 2.1 三条红线

```
╔═══════════════════════════════════════════════╗
║         每次写入前，必须过三关               ║
╠═══════════════════════════════════════════════╣
║ ① 结论还是流水账？  只保留结论。            ║
║    禁止：终端输出全文、对话逐字记录          ║
║                                             ║
║ ② 30天后还值得看吗？ 值得才写。             ║
║    不值得：今天跑了什么命令、临时调试记录    ║
║                                             ║
║ ③ 有同主题文件了吗？ 有→追加，没有→新建。  ║
║    禁止：每次对话新建一个时间戳文件          ║
╚═══════════════════════════════════════════════╝
```

### 2.2 格式模板

#### 新文件（话题首次出现）

```markdown
---
created: 2026-05-15
updated: 2026-05-15
agent: media
category: 决策
status: 活跃
confidence: 已验证
importance: ⭐⭐⭐
source: 实践
tags: [cloakserve, CDP, 技术选型]
---

# 话题名

## 核心结论（Time: 2026-05-15）

### 结论
一句话核心结论。

### 理由
- 理由 1 — 事实/数据
- 理由 2 — 事实/数据

### 详情（可选）
展开说明。

### 下一步
- [ ] 行动项
```

#### 追加到已有文件

```markdown

---

## 新条目（Time: 2026-05-15）

### 结论
...

### 理由
...

### 下一步
- [ ] ...
```

### 2.3 禁止的内容模式

| ❌ 禁止 | ✅ 替代 |
|---------|--------|
| `🧑 今天的任务是...🤖 好的，我开始执行...`（对话流水账） | `## 结论：完成了X任务，使用了Y方案` |
| `brew install node wget curl git`（终端命令全文） | `## 结论：工具链搭建完成，关键依赖：node@18, wget` |
| `2026-05-15_182501_银月传媒·任务执行...md`（时间戳文件名） | `CloakServe集成.md`（话题文件名） |
| 重复的标题头、Agent 签名、会话上下文重复出现 | 只写精华内容，不罗列上下文 |

## 第四章：Daily 日报规范

### 4.1 内容纪律

```
┌──────────────────────────────────────┐
│          每个 Agent 每天 3 行        │
│                                      │
│  第一行：决策（今天定下了什么）      │
│  第二行：知识/流程（今天学到了什么） │
│  第三行：状态（任务进行/完成/阻塞）  │
│                                      │
│  超过 3 行 = 没提炼到位             │
└──────────────────────────────────────┘
```

### 4.2 格式

```markdown
## 银月传媒

### 决策
- **CloakServe 方案定稿** → [[决策/银月｜CloakServe集成]]
  选用 cloakserve v0.25，5 种子池。

### 状态
- 📌 CloakServe 压测 — 进行中
- ✅ 小红书调研 — 已完成
```

**核心规则：**
1. 结论先行 — 每行以加粗结论开头
2. 链接优先 — 详情链回 vault 对应文件，不重复全文
3. 不写纯日志 — "今天跑了什么命令" 不写
4. 不重复上下文 — 不需要再做自我介绍

## 第五章：文件生命周期

### 5.1 状态流转

```
创建（status: 活跃）
  │
  ├─ 持续更新 → 保持活跃
  │
  ├─ 暂时搁置（>30天无更新）→ 冻结
  │
  └─ 被新内容替代 → 在原文件中标记：
      1. `deprecated_by: [[新文件]]`
      2. `status: 归档`
      3. 旧内容打上 ~~删除线~~
```

### 5.2 对话记录的淘汰

`Agents/*/对话记录/` 是缓存，不是知识资产：

- 保留最近 7 天，超期自动淘汰
- 有价值的决策/知识/流程/成果 → 提取到对应 4 分类
- 不写 frontmatter，不做链接

### 5.3 旧文件处理

旧结构（`项目/` `知识库/` `产出/`）中的文件：

- 标记 `status: 归档`（不删除）
- 不再被同步脚本处理
- 引用时加注释 `> 旧版，参见 [[新文件]]`

## 第六章：Agent 专属注意事项

### 6.1 media（银月传媒）

- **内容型 agent**，知识更新快，注意区分「知识/」和「流程/」
  - 了解到一个创作技巧 → 知识/
  - 总结出可重复的创作步骤 → 流程/
- **热点趋势简报** → 成果/（有时间属性）
- 封面生成 → 流程/（可重复执行）

### 6.2 global（梅凝出海）

- **繁体中文 + 台湾用语**输出，frontmatter 和文件名保持简体
- 地域性研究（台湾、东南亚）→ 在 tags 中标注地域
- 多平台运营（Shopify、虾皮、TikTok Shop）→ 每个平台独立文件

### 6.3 edu（元瑶教育）

- 教学设计和学习路径 → 知识/
- 课程大纲和课件 → 成果/
- 课程录制、学员跟进步骤 → 流程/

### 6.4 shared（玄骨中枢）

- **基础设施变更** → 决策/（用 `status: 活跃` 标记当前架构，`deprecated_by` 标记旧架构）
- 故障复盘 → 知识/
- 运维操作 → 流程/

### 6.5 side（宋玉创业）

- 方向选择（不做某事也是决策）→ 决策/
- 市场验证过程 → 知识/
- MVP 构建步骤 → 流程/

## 第七章：脚本行为绑定

### 7.1 sync_memory.py 的合规检查

自动分类时触发以下检查：

```python
# 伪代码逻辑
if 文件已存在 and 话题匹配:
    → 追加模式（更新 updated 日期）
elif 新话题:
    → 按模板创建新文件
else:
    # 内容太短（< 100字符）或只有对话流水账
    → 拒绝写入，输出警告

# 质量检查
if 正文.startswith("🧑" or "🤖"):
    → 警告："检测到对话原始格式，请提炼后写入"
    → 自动去除 emoji 前缀，提取结论行
```

### 7.2 obsidian_sync.py 的合规检查

- 旧命名文件（`agent_category_date.md`）→ 自动映射到 v4 分类
- 旧 Daily 文件 → 自动聚合到 `Daily/<date>.md`

## 第八章：违规处理

| 违规行为 | 处理 |
|----------|------|
| 对话流水账写入知识分类 | sync_memory 自动拒绝，日志警告 |
| 时间戳文件名 | 脚本自动拒绝，提示改为话题名 |
| 缺少必填 frontmatter 字段 | 脚本自动补全，记录到 daily 日志 |
| frontmatter 分类名错误 | 自动修正，输出修正日志 |
| 超过 7 天的对话记录 | 脚本自动删除（不进入 vault） |
