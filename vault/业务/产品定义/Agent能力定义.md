## 元瑶 Phase0 启动清单

> 时间：2-3周（与原Phase 1并行执行）
> 目标：诊断Agent Pilot上线 → 跑通数据管道 → 验证核心指标 ≥ 80%
> 前提：工程团队先回答3个埋点问题

================================================================================
先决条件：工程团队回答3个问题（1天）
================================================================================

问题1：课件前端是否有操作轨迹埋点？
- 即：学员点击序列、拖拽轨迹、答题用时是否能实时记录？
- 如果"是" → 走"实时诊断模式"（最优）
- 如果"否" → 走"课后答题分析模式"（备选，基于已有点击结果做BKT推断）

问题2：课后答题结果能否导出到外部系统？
- 格式：学员ID + 题目ID + 对/错 + 用时
- 频率：实时 / 每日批次

问题3：课后练习系统是否有API可接入？
- 用于教练Agent推送针对性的补充练习

回答方式：飞书回复或在edu/curriculum/tech-assessment-agent-plan.md中标注

================================================================================
Week 1：诊断Agent基建（5个并行任务）
================================================================================

任务1.1 — 数据管道搭建（2天，工程）
负责人：工程团队
交付物：学员操作数据 / 答题结果可拉取到本地系统
验收标准：能实时/每日获取100个学员的课堂数据样本

任务1.2 — 知识图谱对接（1天，元瑶）
负责人：元瑶
交付物：20种思维方法 → BKT知识点模型映射表
说明：现有edu/curriculum/knowledge_graph.json已覆盖L1-L9
需要将"分类思维"等20种方法 + 每个方法的掌握水平（0-100%）映射到BKT模型
输出：bkt_model_config.json

任务1.3 — 学员画像系统启动（1天，元瑶）
负责人：元瑶
交付物：学员画像JSON模板初始化
说明：edu/memories/students/<open_id>.json 模板已就绪
Phase 0内测100人 → 批量创建100个空画像
输出：students/ 目录下100个初始化文件

任务1.4 — BKT引擎搭建（3天，工程）
负责人：工程
交付物：BKT概率更新脚本
输入：学员答题数据（题目ID→知识点映射）
输出：每个知识点的掌握概率（0-100%）
技术要求：Python + 可选的pymc/bambi（知识点数量180个，轻量级）
验收标准：能处理100个学员 × 20种思维方法 = 2000个知识点状态

任务1.5 — 薄弱点诊断报告模板（2天，元瑶+设计）
负责人：元瑶
交付物：面向教师+家长的两版报告HTML原型
教师版：见agent-ux-prototype.md → "课后薄弱点标注报告"
家长版：简化版，3个薄弱点以内 + 建议行动
验收标准：设计稿确认可用

Week 1 检查点（Day 5）
[ ] 数据管道可拉取100个学员数据
[ ] BKT模型映射表完成
[ ] 100个学员初始化画像创建
[ ] BKT引擎跑通一次完整链路（数据输入→概率输出）
[ ] 报告原型设计确认

================================================================================
Week 2：诊断Agent Pilot（8天）
================================================================================

任务2.1 — 100人Pilot学员招募（1天，运营）
负责人：运营团队
标准：
- L1-L5级别，年龄4-9岁
- 近2周至少2节课的活跃学员
- 家长已授权（合规前置条件：监护人同意书）
- 排除：试听期学员、已有流失风险学员
输出：Pilot学员名单（100人）

任务2.2 — A/B测试分组（0.5天，数据）
负责人：数据团队
方式：按Level（L1-L2/L3-L4/L5）、班型（基础/提高/拔高）分层随机分配
输出：实验组50人 + 对照组50人 名单
记录到ab-test-plan.md

任务2.3 — 前3天数据管道压力测试（Day 1-3，工程）
负责人：工程
动作：只跑数据管道，不输出诊断报告
验证：
- 数据能稳定拉取
- 无数据丢失
- 延迟在可接受范围（实时<5s / 批次<30min）
如果数据管道不稳定 → 回退到"课后答题分析模式"

任务2.4 — 诊断报告上线（Day 4，全组）
动作：
- 实验组：老师开始收到"课后薄弱点标注报告"
- 对照组：维持现有课次报告
每日记录：
- 诊断准确率：Agent标注的薄弱点 → 老师人工复核确认的比例
- 诊断耗时：Agent生成报告时间
验收标准：准确率 ≥ 80%，耗时 < 5秒

任务2.5 — 家长端报告上线（Day 6，全组）
动作：
- 实验组家长：收到升级版课次报告（含薄弱点分析和建议）
- 每日记录家长打开率
验收标准：家长打开率比对照组高10个百分点

Week 2 检查点（Day 12）
[ ] Pilot学员确认100人
[ ] A/B分组完成
[ ] 数据管道压力测试通过（3天无异常）
[ ] 诊断报告上线Day 4-7运行正常
[ ] 准确率 ≥ 80%
[ ] 家长端报告打开率提升

================================================================================
Week 3：教练Agent规划 + 合规 + 总结
================================================================================

任务3.1 — 教练Agent话术模板预审核（3天，元瑶+教研）
负责人：元瑶输出话术模板，教研团队审核
交付物：20种思维方法 × 3种情况（正确/部分正确/错误）的追问话术库
说明：话术必须预审核通过才能在教练Agent中使用
原则：不直接给答案，苏格拉底式引导

任务3.2 — FSRS排期模块搭建（2天，工程）
负责人：工程
交付物：py-fsrs集成脚本
输入：知识点掌握概率（来自BKT）+ 上一次复习时间
输出：下一次最优复习时间
验收标准：能计算180个知识点的独立复习排期

任务3.3 — 可视化Agent报告模板设计（2天，元瑶+设计）
负责人：元瑶
交付物：能力增长曲线 + 20种思维雷达图 + 成长动画原型
说明：设计稿确认后，工程实施

任务3.4 — 合规动作执行（并行）
负责：法务
P0动作：
- 用户协议增加"AI诊断"条款
- 家长端增加AI功能说明弹窗
P1动作：
- 教练Agent话术预审核（3.1）
- 确认70%校内拓展的合规表述
- 操作轨迹采集的监护人同意书措辞

任务3.5 — Phase 0总结报告（Day 21，元瑶）
交付物：Phase 0 Pilot完整报告
内容：
- 诊断Agent准确率：X%
- 诊断耗时：X秒
- 家长打开率提升：X个百分点
- 老师反馈摘要
- 是否具备全量上线条件
- Phase 1-3计划是否需要调整

Week 3 检查点（Day 21）
[ ] 教练Agent话术模板通过审核
[ ] FSRS排期模块可运行
[ ] 可视化Agent设计稿确认
[ ] 合规P0动作完成
[ ] Phase 0总结报告输出

================================================================================
团队协作方式
================================================================================

每日站会（10分钟）
- 看当天任务完成状态
- 看数据管道是否稳定
- 看诊断Agent准确率趋势
- 决策：是否有障碍需要升级

协作工具
- 飞书多维表格：Phase 0任务看板
- 飞书文档：所有产出的模板/报告集中管理
- edu/curriculum/ 目录：技术文档版本管理

================================================================================
退路方案
================================================================================

如果埋点不支持实时操作轨迹追踪：
→ 退回到"课后答题分析模式"
→ 基于答题对错做BKT推断（不需要埋点数据）
→ 诊断准确率可能从预期85%降到70-75%
→ 不影响教练Agent和可视化Agent

如果100人内测诊断准确率 < 70%：
→ 排查BKT模型参数
→ 调整知识点-题目的映射关系
→ 增加老师人工复核环节
→ 延迟全量上线，延长Pilot周期1-2周
