# Vault YAML 合规全线修复记录

> 修复时间：2026-05-18
> 触发：Obsidian 客户端弹红框 YAML 解析错误
> 终态：103 文件，零 YAML 错误 ✅

---

## 问题现象

Obsidian 打开后持续弹红框报错，提示 YAML frontmatter 解析失败。

## 排查结果

### 🔴 已发现的 3 类 YAML 破坏模式

| 模式 | 原因 | 示例 |
|------|------|------|
| `source: 对话: session_xxx` | YAML 值内未加引号的 `:` | 33 文件 |
| `source: "系统审计: 2026-05-16..."` | 同上（含空格+时间戳） | 2 文件 |
| `related: [[wiki1]], [[wiki2]]` | 未加引号的值含 `,` + `[` | 2 文件 |
| 单行 `---\ndate:...\n---` | 脚本把 `\n` 写成字面量而非真实换行 | 2 文件 |

### 共计修复 39 文件（33 批量 + 6 手工）

---

## 根因修复（写入脚本层面）

### 1. sync_memory.py（管道引擎）— 第 658 行
```python
# 修复前
"source": f"对话: {session_path.stem}"

# 修复后
"source": f'"对话: {session_path.stem}"'   # 值自带双引号，生成 source: "对话: xxx"
```

### 2. collect_architecture.py — 3 处 `\\n` → `\n`
- 第 266 行：`"\n".join(lines)`（架构文档）
- 第 319 行：`"\n".join(lines)`（记忆映射 Agent 详情）
- 第 366 行：`"\n".join(lines)`（记忆映射追加段）

### 3. collect_architecture.py — v3.0 命名 + 覆写 bug
- `architecture.md` → `系统｜架构.md`
- `memory-map.md` → `系统｜记忆映射.md`
- Agent 配置详情 + 记忆映射两段原写入同一文件互相覆写 → 改为追加模式

### 4. media/scripts/sync_memory.py — 3 处修复
- `---` 从文件末尾移到开头（现在生成真正 YAML frontmatter）
- `source: {source}` → `source: "{source}"` （引号保护）
- `tags: a, b` → `tags: ["a", "b"]`（YAML 流序列语法）

### 5. edu/scripts/sync_memory.py — tags 格式
- `"edu/memory edu/agent"` → `"edu/memory, edu/agent"`（YAML 流序列需逗号分隔）
