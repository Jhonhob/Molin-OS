    24|## 一、Prompt 工程模板（源于 bolt.new 源码提炼）
    25|
    26|### 核心结论
    27|
    28|AI Agent 的 Prompt 不是「写一段话」，而是**用结构化标签构建一个可预测、可解析、可执行的系统**。bolt.new（16,370⭐）用 6 个 XML 标签 + 14 条行为规范 + 3 个 Few-shot 示例，做到了 AI 输出的精确控制。
    29|
    30|### 关键要点
    31|
    32|1. **六层标签体系**：identity → constraints → capabilities → behavior_rules → output_format → examples，信息流从「我是谁」到「具体怎么做」层层递进
    33|2. **输出可解析**：bolt.new 用 `<boltArtifact>` + `<boltAction>` 包裹 AI 输出，前端流式解析器逐标签处理，实现 AI 输出 → 自动化执行的闭环
    34|3. **约束具体化**：不说「输出要规范」，而是「用 XML 标签包裹，标签类型不超过 5 种」
    35|4. **Few-shot 是放大器**：3 个完整示例（简单/中等/复杂），覆盖 80%+ 场景
    36|5. **五大原则**：标签语义化、约束具体化、示例完整化、输出可解析、信息流层次化
    37|
    38|### 详细内容
    39|
    40|#### 通用结构化 Prompt 模板
    41|
    42|```
    43|你是一个[身份定义]，具备[核心能力描述]。
    44|
    45|<identity>
    46|  Agent的身份名称、角色定位、核心专长
    47|</identity>
    48|
    49|<constraints>
    50|  环境约束和行为限制
    51|  - 能力边界：能做什么，不能做什么
    52|  - 资源限制：调用API的频率上限、数据范围
    53|  - 安全规则：不能做什么，必须做什么
    54|  - 格式约束：输出必须遵循的格式
    55|</constraints>
    56|
    57|<capabilities>
    58|  能力清单，逐条列出Agent拥有的能力
    59|  - 能力1：描述 + 调用方式 + 参数说明
    60|  - 能力2：描述 + 调用方式 + 参数说明
    61|</capabilities>
    62|
    63|<behavior_rules>
    64|  行为规范，约束Agent的响应方式
    65|  - 回复风格：简洁/详细/正式/亲切
    66|  - 交互方式：是否需要确认/是否自动执行
    67|  - 错误处理：遇到问题时如何处理
    68|  - 优先级：多条规则冲突时怎么处理
    69|</behavior_rules>
    70|
    71|<output_format>
    72|  输出格式规范（最关键部分！）
    73|  定义输出的结构化格式，让下游系统能精确解析
    74|</output_format>
    75|
    76|<examples>
    77|  示范：展示3个完整的输入→输出示例
    78|  每个示例包含：用户输入 + Agent完整输出（带标签结构）
    79|</examples>
    80|```
    81|
    82|#### bolt.new 原版 Prompt 结构分析（284行，7个标签）
    83|
    84|| 标签 | 功能 | 设计要点 |
    85||------|------|---------|
    86|| system_constraints | 环境约束 | 先说明是什么环境，再说明不能做什么 |
    87|| code_formatting_info | 代码格式 | 极简，只说关键 |
    88|| message_formatting_info | 消息格式 | 限制可用 HTML 元素 |
    89|| diff_spec | 文件变更格式 | 定义输入格式（GNU unified diff） |
    90|| artifact_info/instructions | 核心行为规范 | 14 条规范层层递进 |
    91|| 约束指令 | 5 条关键约束 | NEVER use "artifact", 不啰嗦, 先思考再回答 |
    92|| examples | Few-shot 示例 | 3 个完整示例（阶乘 / 贪吃蛇 / React 弹跳球） |
    93|
    94|#### AI 输出最终格式
    95|
    96|```xml
    97|<boltArtifact id="project-name" title="Project Title">
    98|  <boltAction type="shell">npm install ...</boltAction>
    99|  <boltAction type="file" filePath="src/index.js">完整文件内容</boltAction>
   100|  <boltAction type="shell">npm run dev</boltAction>
   101|</boltArtifact>
   102|```
   103|
   104|#### 四个可直接复用的场景模板
   105|
   106|- **场景一：企业信息查询 Agent** — identity + constraints(只回答企业相关) + capabilities(查询/经营/风险) + output_format(enterprise_report)
   107|- **场景二：数据爬取清洗 Agent** — constraints(遵守 robots.txt, 频率≤1次/秒) + capabilities(提取/清洗/转换) + output_format(data_task)
   108|- **场景三：代码生成 Agent** — 直接复用 bolt.new 模式，完整代码不用占位符
   109|- **场景四：自动化流程 Agent** — 每步检查前置条件 + 敏感操作二次确认 + output_format(flow_execution)
   110|
   111|#### Prompt 工程五大原则
   112|
   113|| 原则 | 解决的问题 | 正例 vs 反例 |
   114||------|-----------|-------------|
   115|| 标签语义化 | 各维度信息分离 | 6 个标签各司其职 |
   116|| 约束具体化 | 避免模糊指令 | "200字以内" vs "不要输出不相关内容" |
   117|| 示例完整化 | AI 理解交互模式 | 完整输入输出 vs 只说"类似这样" |
   118|| 输出可解析 | 下游系统能消费 | XML 标签嵌套≤2层 vs 自由文本 |
   119|| 信息流层次化 | 认知顺序正确 | identity→constraints→capabilities→behavior→output→examples |
   120|
   121|#### 验证与迭代
   122|
   123|- 一致性测试：同一问题问 3 次，输出格式一致
   124|- 边界测试：给超出范围的问题，遵守 constraints
   125|- 解析测试：解析器解析输出，成功率>95%
   126|- 负向测试：模糊/错误输入，合理拒绝或澄清
   127|
   128|迭代建议：最小化启动 → 按需添加 → 单一职责 → 渐进增强 → 格式做减法
   129|
   130|#### 对墨麟副业的价值
   131|
   132|- 接单时直接套用 4 个场景模板
   133|- 差异化价值：不是只改 prompt 文案，而是有完整结构化工程
   134|- 交付物：每个 Agent 附带 Prompt 工程文档 + 输出格式规范 + 测试用例

   176|
   177|**六大核心模块**：
   178|
   179|| 模块 | 文件 | 行数 | 核心设计 |
