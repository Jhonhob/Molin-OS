## 二、🔴 SOP 改进提案 #1: KPI 数据管道容错

### 问题
Cron Step 5 静默失败 → 22 Agent 数据黑盲 → 财务/品控/成本全线失效

### 改进方案

在现有 Cron SOP KPI写入步骤之后追加：

```yaml
Step 5b — KPI 写入验证门控:
  1. 写入后立即检测 relay/kpi/{agent}_{today}.json 存在性
  2. 不存在 → 重试 3 次 (间隔 30s)
  3. 3 次失败 → 写入 relay/kpi/{agent}_{today}.fallback.json
  4. 触发飞书 L1 通知: "KPI管道告警 - {agent} - {date}"
  5. 每日 22:00 墨数清洗检测所有 fallback 文件

Step 5c — KPI 健康巡检 (执行前):
  1. 检查 relay/kpi/ 最近日期 >= 昨天
  2. 缺失 → 先执行 KPI 追溯管道，再执行主任务
```

**验收**: 连续7天无KPI空白日；单次失败后30秒内自愈

### 关联根因链
KPI 管道失效 → 元瑶 KPI 偏离未被及时捕获 (5/21 mirofish_probe 才告警) → 管理层盲区 → 周末/平台收缩等 hidden patterns 全靠墨数复盘后知后觉

## 三、🔴 SOP 改进提案 #2: 外部依赖自动续期

### 问题
小红书 Cookie 7+天失效无自动修复 → 内容发布管道完全阻塞

### 改进方案

```yaml
外部认证生命周期管理:
  
  前置检查 (每日 06:00): 检查所有发布平台 Cookie 状态
  - 有效且剩余 < 3天 → 提前续期
  - 失效 → 执行续期流程
  
  续期流程:
    1. Playwright 无头浏览器执行 OAuth 登录
    2. 验证新 Cookie 可用性 (测试发布 API)
    3. 失败 → 降级到备用通道
    4. L1 飞书通知创始人
  
  多通道 Fallback:
    - 🟢 主通道: 小红书 + Cookie
    - 🟡 备用: 内容存入 产出/银月｜待发布积压.md 标记 📌
    - 🔴 终级: 手动发布清单写入 Obsidian
```

**验收**: Cookie 失效后30分钟内自动恢复或完成降级；无内容因发布阻塞损失超过24h

## 五、成功案例提炼🎯

### 🏆 系统稳定性纪录
- **成果**: Feishu WS 创 ~31.5h 零断连; Gateway 7/7 持续在线; 健康分 85%
- **要素**: 高频巡检(每5') + 自动自愈
- **复用 → KPI 管道**: 将巡检范式迁移到数据管道：每5分钟 relay/kpi/ 新鲜度检测

### 🏆 规模经济效应反直觉发现
- **成果**: 高产出日(≥6任务) CPT ¥0.535 vs 低产出日(≤3任务) ¥0.749 → 40%成本优势
- **要素**: 墨数深度挖掘 + 反直觉洞察 (产出越高质量越高)
- **复用**: 任务队列攒够4件触发批量执行模式

### 🏆 财务降级韧性
- **成果**: 即使KPI完全中断，墨算仍产出完整估算报告；月预算仅 2.7%
- **要素**: "数据可用性降级模式" — 不完美但从不空白
- **复用 → KPI 管道**: 主数据不可用时使用上日基线+置信度标注

### 🏆 内容产需解耦
- **成果**: 发布管道阻塞不影响创作管道(5/23调度4个包)
- **要素**: 银月·墨排调度 + 内容 | 发布解耦
- **复用**: 创作者与发布者之间的"就绪队列"模式
