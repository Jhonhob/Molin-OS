# 教育费曼Agent设计方案

> **核心定位**：让学员通过"教 AI"来检验自己的理解。不是 AI 教人，而是人教 AI——在教的过程中暴露理解漏洞。

---

## 开篇：为什么需要费曼Agent——从被动输入到主动输出的跨越

> **情境（Situation）**：元瑶教育现有的三Agent体系（Coach Agent 苏格拉底式追问、诊断Agent 量化分析、可视化Agent 报告生成）已经覆盖了"AI引导→学员回答→数据追踪→可视化反馈"的完整教学闭环。2026年5月的数据显示，学员完课率达72%，薄弱点定位准确率78%。
>
> **冲突（Complication）**：但有一个根本性问题始终存在——**学员以为自己懂了**。Coach Agent 是 AI 问、学员答，学员能回应问题不代表能独立讲解。传统课堂中有一个经典现象：学生能做对题（被动输出），但讲不清楚原理（主动输出）。在 AI 教育场景中同样存在：系统追踪到 BKT 掌握概率≥0.6，但学员仍然无法用自己的语言复述知识点。这是**假性理解**——被动认知和主动建构之间的鸿沟。
>
> **疑问（Question）**：能否设计一个 Agent，让学员从"被提问者"变成"教学者"，通过教 AI 来彻底暴露理解漏洞？
>
> **回答（Answer）**：费曼Agent——基于诺贝尔物理学家理查德·费曼的学习法，构建一个"谦虚的学徒"角色，让学员在"教人"的过程中自动化暴露术语依赖、逻辑跳步、类比缺失、卡壳点四大类漏洞，并与现有 BKT/IRT/知识图谱引擎深度联动。

### 决策博弈：为什么自研费曼Agent而非复用已有框架？

| 方案 | 优势 | 劣势 | 决定 |
|------|------|------|------|
| **Coach Agent 改造** | 零开发量，复用现有架构 | Coach Agent 的角色是"提问者"，改成"学徒"会混淆人格定位；对话流程完全不同（问→答 vs 听→反馈） | ❌ 否决：角色冲突不可调和 |
| **外部 LLM Prompt 模板** | 快速原型（几小时） | 依赖LLM API 成本、延迟不可控、无法离线运行；纯规则版可以零成本运行 | ❌ 否决：MVP阶段需要离线可用 |
| **纯规则引擎（自研）** | 零API成本、毫秒级响应、可离线 | 需要开发5类检测器、灵活性低于LLM | ✅ 采用：P0用规则引擎，P2升级LLM增强版 |
| **第三方教学平台集成** | 现成功能 | 无法与现有BKT/IRT/知识图谱引擎深度联动 | ❌ 否决：技术耦合度不够 |

**妥协记录**：P0纯规则引擎意味着初期检测准确率有限（目标≥80% vs LLM版预期≥92%），但在无API成本的约束下，这是最优解。P2阶段引入LLM增强版后，两条路径并行（规则引擎兜底、LLM增强优先）。

## 一、与现有三Agent的分工矩阵

费曼Agent不是替代现有 Agent，而是补齐"知识输出阶段"的能力缺口。

| 维度     | Coach Agent          | 诊断Agent   | 可视化Agent  | **费曼Agent（新增）**       |
| ------ | -------------------- | --------- | --------- | --------------------- |
| 角色     | 苏格拉底式追问者             | 数据分析师     | 报告设计师     | **谦虚的学徒**             |
| 提问方    | Agent问               | 系统自动分析    | 系统自动生成    | **学员问 / 学员讲**         |
| 核心机制   | Socratic questioning | BKT/IRT追踪 | 数据可视化     | **Feynman technique** |
| 输出     | 引导学员找到答案             | 概率+漏洞标签   | 学习报告图表    | **暴露学员理解漏洞**          |
| 效果量(d) | 精细探究0.56             | 知识追踪0.48  | 反馈可见性0.42 | **自我解释0.54**          |
| 触发条件   | 新知识首次讲解              | 每次作答后     | 每周/每单元    | **BKT≥0.6 知识点完成后**    |
| 输入阶段   | ✅ 知识输入               | ✅ 学后分析    | ✅ 总结展示    | **❌ 知识输出**            |

### 与Coach Agent的分工边界

| 场景 | 哪个Agent上 | 为什么 |
|------|------------|--------|
| 新知识首次讲解 | Coach Agent | 需要苏格拉底式引导 |
| 学完后测理解深度 | **费曼Agent** | 需要学员自主输出 |
| 做错了需要纠正 | Coach Agent | 需要精确锁定错误点 |
| 觉得懂了但不确定 | **费曼Agent** | 需要验证是否真懂 |
| 复习巩固 | 任一 | 根据状态选择 |
| 闯关模式 | Exploration引擎 | 需要游戏化互动 |

**核心原则**：知识输入阶段→Coach Agent，知识输出阶段→费曼Agent。两个Agent交替使用，形成"输入→输出→反馈→再输入"的闭环。

## 二、费曼学习法四步Agent化

### 费曼学习法原本四步

> 1. **选择概念** → 选一个今天学的知识点
> 2. **教给别人** → 用最简单的语言讲给完全不懂的人听
> 3. **发现漏洞** → 哪里卡住了、哪里需要打比方、哪里用了术语没解释
> 4. **简化重组** → 回到原资料，用更简单的语言重新讲

### Step 1 · 选题

**触发条件**：学员完成一个知识点的学习，满足以下任一条件——

| 条件 | 优先级 | 原因 |
|------|--------|------|
| BKT 掌握概率刚提升至 ≥0.6 | P0（最高） | 最可能产生假性理解，需要"费曼检验" |
| 该知识点 depth_flag=deep | P1 | 需要深度理解的，强制走费曼流程 |
| 学员自主选题 | — | 尊重学员主动性 |

**费曼Agent开场白**：
> "小白，假设我是第一次听说'{知识点名称}'，你来当老师教教我。"

### Step 2 · 教学对话（学员输出）

学员用语音或文字讲解。费曼Agent全程扮演"认真但基础差的学徒"，在关键节点适时反应：

| 学员行为 | 费曼Agent反应 | 检测的漏洞类型 |
|---------|--------------|---------------|
| 用术语不解释 | "等等，你说的'充分条件'是什么意思？能举个生活中的例子吗？" | 术语依赖 |
| 跳步推理 | "我没跟上，从第三步怎么到第四步的？能再讲一遍吗？" | 逻辑跳步 |
| 含糊跳过难点 | "这里我有点迷糊，你能用苹果和香蕉举个例子吗？" | 类比缺失 |
| 讲得清晰易懂 | "哦！我懂了！原来是这样！"（正反馈强化） | —（无漏洞） |
| 自己卡住说不下去 | 沉默3秒 → "要不我们翻一下书，看看哪里漏了？" | 卡壳定位 |

**关键原则**：
- 不能让学员觉得被测试，而是"真的在教一个人"
- 提问要像真实的笨学生，不要像考官
- 每次打断要有明确理由（暴露一个具体漏洞）

### Step 3 · 漏洞检测（Agent端分析）

教学结束后，费曼Agent从5个维度输出一份"理解诊断报告"：

| 检测维度 | 定义 | 严重级别判断 | 检测方法（规则引擎） |
|---------|------|-------------|-------------------|
| **术语依赖度** | 解释中用了多少未解释的专业术语 | 高：使用≥3个未解释术语；低：≤1个 | 预设术语表比对（充分条件/必要条件/逆否/真值……），检查每个术语是否附带解释 |
| **逻辑跳步** | 推理链条中跳过了多少关键步骤 | 高：跳过≥2个关键步骤；中：1个 | 预设标准推理链条，学员讲解顺序与标准链条对比 |
| **类比质量** | 举的例子是否贴切 | 好有类比=真懂，无类比=浅层理解 | 检查是否包含"比如""就像""例如"等类比触发词 |
| **卡壳定位** | 在哪里说不下去了 | 卡壳点=理解薄弱点精确位置 | 检测学员沉默>5秒，或出现"嗯……""那个……""怎么说呢"等卡壳信号 |
| **简化程度** | 能否用一句话讲清楚核心 | 通过要求：≤20字且无术语 | 教学结束后要求"用一句话总结" |

**报告输出格式**：
```json
{
  "kp_id": "L4_假设思维",
  "teaching_duration_sec": 180,
  "flaws_detected": [
    {"type": "术语依赖", "detail": "使用了'充分条件'未解释", "severity": "medium"},
    {"type": "逻辑跳步", "detail": "从P→Q直接跳到¬Q→¬P,跳过逆否推导", "severity": "high"},
    {"type": "卡壳", "detail": "在解释'如果下雨地湿,地湿不一定下雨'时卡住", "severity": "high"}
  ],
  "analogy_quality": 0.3,
  "terminology_ratio": 0.6,
  "can_summarize_in_one_sentence": false,
  "overall_grasp": "表面理解,有几个关键漏洞需补"
}
```

### Step 4 · 简化重组引导

根据漏洞检测结果，引导学员回到原文重新学习：

| 漏洞类型 | 引导话术 |
|---------|---------|
| 术语依赖 | "你能不用'充分条件'这个词，重新讲一遍吗？" |
| 逻辑跳步 | "我们倒回去，从第二步开始一步步来" |
| 卡壳 | "这个地方确实容易迷糊，我们看一段资料，然后你用自己的话再讲一次" |
| 类比质量差 | "这个例子好像不太对，试试用'下雨和带伞'来比喻？" |

**完成标准**：二次讲解的漏洞减少 ≥50% → 标注为该知识点"费曼通关"。

## 三、与现有引擎的联动机制

> 此处展现费曼Agent不是孤立的独立功能，而是嵌入在元瑶教育完整技术栈中的一个数据节点。

### 输出→BKT引擎
| 费曼Agent事件 | BKT反应 | 触发条件 |
|--------------|---------|---------|
| 费曼通关 | 掌握概率额外提升 +0.05~0.10 | 二次讲解通过 |
| 发现严重漏洞(severity=high) | 掌握概率下调 -0.05 | 漏洞被确认 |
| 漏洞类型分布 | 更新学员 memory 的 "understanding_flaws" 字段 | 每次教学结束 |

### 输入←知识图谱
| 知识图谱标记          | 费曼Agent行为       |
| --------------- | --------------- |
| depth_flag=deep | 必须走费曼流程（需要深度理解） |
| depth_flag=tool | 可选走费曼流程（会用即可）   |

### 输入←BKT
| BKT范围     | 费曼Agent行为             |
| --------- | --------------------- |
| BKT ≥ 0.6 | 触发费曼Agent（初步掌握后做深度检测） |
| BKT < 0.6 | 不触发（还没学会就别教人）         |

### 输出→IRT引擎
- 费曼检测出的漏洞知识点 → 纳入IRT自适应出题范围

### 输出→LessonLayerer
| 费曼结果 | LessonLayerer行为 |
| ---- | --------------- |
| 通关   | 推荐升级到挑战层        |
| 未通关  | 推荐保持在标准层        |

## 四、技术实现：从规则引擎到LLM增强

### 对话流程图

```
学员完成L4_假设思维学习 (BKT>=0.6)
    │
    ▼
费曼Agent: "来当老师教我"
    │
    ▼
学员讲解 (语音/文字 转文本)
    │
    ▼
费曼Agent实时检测:
  ├─ 语义分析 → 术语密度、逻辑连贯性、卡壳检测
  ├─ 类比检测 → 是否有生活化例子
  └─ 简化检验 → 能否一句话总结
    │
    ▼
教学结束 → 生成理解诊断报告
    │
    ▼
漏洞反馈 + 简化重组引导
    │
    ▼
学员二次讲解
    │
    ▼
通过 → BKT奖励 + 推荐挑战层
未通过 → BKT回调 + 推送补学材料
```

### 纯规则引擎版（P0，无LLM依赖）

| 检测器 | 实现方式 | 预期准确率 |
|-------|---------|-----------|
| 术语检测 | 预设术语表比对 | ≥85% |
| 跳步检测 | 标准推理链条对比 | ≥80% |
| 类比检测 | 触发词识别（比如/就像/例如） | ≥75% |
| 卡壳检测 | 沉默>5秒 + 犹豫信号词 | ≥90% |
| 简化检测 | 字数限制 + 术语检查 | ≥95% |

**整体准确率目标**：≥80%（P0），≥92%（P2 LLM增强版）

### LLM增强版（P2，有条件启用）

```
你是费曼学习法的教练Agent。
你的角色是一个"谦虚的学徒"，完全不懂{知识点}。

让学员用最简单的语言教你。
规则:
- 当学员用专业术语时,说"我不懂这个词,能举个生活中的例子吗?"
- 当学员跳步时,说"我没跟上,能再讲一遍第X步到第Y步吗?"
- 当学员说得很清楚时,说"哦!我懂了!原来是这样!"
- 当学员卡住时,等3秒,说"要不我们查一下资料?"
- 绝对不要让学员觉得你在考试他
- 教学结束后,生成一份理解漏洞报告
```

## 五、阶段规划与交付标准

| 阶段 | 时间 | 功能范围 | 依赖 | 交付标准 |
|------|------|---------|------|---------|
| **P0 MVP** | 2-3周 | 文本输入 + 5类规则检测器 + BKT联动 | 预设术语表 + 推理链条库 | 漏洞检测准确率≥80% |
| **P1 对话增强** | 2周 | 费曼话术模板 + 类比触发词 + 二次对比 | 标准反应库 | 漏洞修复率评估可用 |
| **P2 LLM增强** | 3-4周 | LLM语义理解 + 动态追问 + 语音输入 | LLM API | 检测准确率≥92% |

### 可用性测试方案

| 测试 | 场景 | 预期结果 | 通过标准 |
|------|------|---------|---------|
| 测试1 | 找教研老师（真懂） | 术语依赖低，类比质量高，能一句话总结 | 检测判定为"通透" |
| 测试2 | 找刚学完的学员（BKT≈0.7） | 检出1-2个漏洞 | 漏洞检出准确率≥80% |
| 测试3 | 找没学过的学员 | 大量术语依赖+跳步+无法总结 | 检测判定为"需要补学" |

## 六、异常边界与风险兜底

| 风险场景 | 概率 | 影响 | 预防措施 | 应急处理 |
|---------|------|------|---------|---------|
| 学员沉默不说话 | 中 | 低 | 开场暖场话术"别紧张，随便教我" | 3次鼓励后→切换回Coach Agent |
| 学员讲偏了完全跑题 | 低 | 中 | Limiter 检测教学内容与选题的语义相似度 | 温和引导"我们还是说回{知识点}？" |
| 学员突然问费曼Agent问题 | 中 | 中 | 预设回答模板"我不太确定，你觉得呢？" | 对话管理模块将反问重定向回学员 |
| 故障检测器全漏报 (all clear 但实际不懂) | 中 | 高 | 二次讲解+漏洞率对比；P2阶段LLM交叉验证 | 标记为"费曼结果存疑"→人工复核 |
| 学员语音输入质量差 | 低 | 中 | 文字输入作为fallback | ASR失败→提示"请打字告诉我" |
| P0规则引擎准确率不达标 | 中 | 高 | 设置准确率监控dashboard，每周核查 | 不达标时推迟P1→回炉改进检测器 |
