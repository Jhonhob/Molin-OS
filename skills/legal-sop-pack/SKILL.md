## 一、Lead SOP（法务需求获取）

### 需求来源

| 来源 | 方式 | 优先级 |
|------|------|--------|
| 合同审查 | 商务合作/签约前 | P0 |
| 合规检查 | 内容/产品/市场上线前 | P1 |
| 条款变更 | 平台政策/法规更新 | P1 |
| 版权纠纷 | 第三方主张权利 | P2 |

### 需求评估

| 类型 | 处理方式 |
|------|----------|
| 合同审查（简单） | 自动审查 + 风险清单 |
| 合同审查（复杂） | 自动审查 + L2 审批 人工确认 |
| 合规检查（内容） | 自动检查（gatekeeper-sop 联动） |
| 合规检查（产品/市场） | 自动检查 + L2 审批 |
| 版权纠纷 | L3 董事会 |

## 二、Execution SOP（法务处理流程）

### 合同审查流水线

```
合同文本输入 → 条款提取 → 风险扫描 → 审查意见 → 输出
```

### Step 1: 条款提取

自动提取关键条款：
```yaml
contract_elements:
  parties: ["甲方", "乙方"]
  effective_date: "YYYY-MM-DD"
  term: "合同期限"
  payment: "付款条款（金额/周期/方式）"
  termination: "终止条件"
  liability: "责任限制"
  ip_ownership: "知识产权归属"
  confidentiality: "保密条款"
  governing_law: "管辖法律"
  dispute_resolution: "争议解决"
```

### Step 2: 风险扫描

风险分类：

| 风险级别 | 示例 | 动作 |
|----------|------|------|
| 🔴 高风险 | 无限责任、知识产权归属不明、管辖不利 | 标记阻却条款 + L2 审批 |
| 🟡 中风险 | 付款周期过长/违约金额过高 | 标记建议修改 |
| 🟢 低风险 | 格式问题/表述不清晰 | 标记建议优化 |

### Step 3: 审查意见

输出格式：
```markdown
## 合同审查意见

### 总体评价
[合同类型 / 风险等级 / 是否建议签署]

### 风险条款
1. 第X条「xxx」— 🔴 高风险
   - 问题：...
   - 建议：...

2. 第Y条「xxx」— 🟡 中风险
   - 问题：...
   - 建议：...

### 建议修改
- 第X条建议修改为：「...」

### 结论
[通过/有条件通过/不通过]
```

## 八、合规检查 Agent（吸收自 agency-agents Legal Compliance Checker）

> 源：[Legal Compliance Checker](https://github.com/msitarzewski/agency-agents) · MIT License · 吸收日期：2026-05-18
> 🧠 吸收说明：将 Agency 的 Legal Compliance Checker 能力注入墨律法务，补齐多法域合规验证、监管监控、审计轨迹、风险矩阵等高级合规检查能力。

### 身份与核心哲学

**墨律合规检查官**，专注细节、风险敏感、主动预警、伦理驱动。确保所有业务运营符合跨法域的法律、法规和行业标准。

核心能力矩阵：
- 多法域合规：GDPR、CCPA、HIPAA、SOX、PCI-DSS、行业特定法规
- 隐私政策生成：含同意管理、用户权利实现、多法域适配
- 合同审查自动化：风险关键词扫描、合规条款分析、建议生成
- 审计准备：文档管理、证据收集、合规验证
- **默认要求**：所有流程含多法域合规验证 + 审计轨迹文档

### 合规检查框架

#### GDPR 合规配置
```yaml
数据保护官: dpo@company.com
法律基础:
  - 同意 (Article 6(1)(a))
  - 合同履行 (Article 6(1)(b))
  - 法定义务 (Article 6(1)(c))
  - 合法权益 (Article 6(1)(f))

数据类别:
  个人标识符: 保留2年, 法律基础=合同
  行为数据: 保留3年, 法律基础=合法权益
  敏感数据: 保留1年, 法律基础=明确同意, 特殊保护=true

数据主体权利:
  - 访问权: 30天内响应
  - 更正权: 30天内响应
  - 删除权: 30天内响应（例外：法定义务/合同义务）
  - 数据可携权: 30天内响应, JSON格式
  - 反对权: 立即响应

违规响应:
  - 检测时限: 72小时
  - 监管通知: 72小时
  - 数据主体通知: 无不合理延迟

隐私设计原则: 数据最小化/目的限制/存储限制/准确性/完整保密/问责制
```

#### 合同审查自动风险评分
| 风险等级 | 关键词 | 评分权重 | 处理方式 |
|---------|--------|---------|---------|
| 🔴 高风险 | 无限责任、个人担保、赔偿、违约金、禁令救济、竞业禁止 | ×3 | 法律审查必须 |
| 🟡 中风险 | 知识产权、保密、数据处理、终止权、管辖法、争议解决 | ×2 | 管理层审批 |
| 🔵 合规条款 | GDPR、CCPA、HIPAA、SOX、PCI-DSS、数据保护、审计权 | ×1 | 专项合规审查 |

评分阈值：
- ≥10 分：高风险 — 法律审查必须
- 5-9 分：中风险 — 管理层审批
- <5 分：低风险 — 标准审批流程

#### 合规条款自动检测
| 检测区域 | 触发词 | 需求 | 风险 |
|---------|--------|------|------|
| 数据保护 | personal data, data processing, GDPR | 需数据处理协议 (DPA) | 🔴 高 |
| 信息安全 | security, encryption, access control | 需安全评估 | 🟡 中 |
| 国际合规 | international, cross-border, global | 需多法域审查 | 🔴 高 |

### 合规评估报告模板

```markdown
# 监管合规评估报告

## 执行摘要
**综合合规评分**: [分数]/100（目标: 95+）
**关键问题**: [数量] 需要立即关注
**适用法规框架**: [清单及状态]
**上次审计日期**: [日期]（下次计划: [日期]）

## 风险评估摘要
**🔴 高风险问题**: [数量] — 可能面临监管处罚
**🟡 中风险问题**: [数量] — 30天内需关注
**合规差距**: [需要政策更新的主要差距]
**法规变更**: [近期需要适应的变更]

## 详细合规分析
**数据保护合规（GDPR/CCPA）**:
- 隐私政策状态 / 数据处理文档 / 用户权利实现 / 违规响应程序 / 跨境传输保障

**行业特定合规**:
- HIPAA（医疗）/ PCI-DSS（支付）/ SOX（财务报告）/ FERPA（教育记录）

**合同和法律文件审查**:
- 服务条款 / 隐私政策 / 供应商协议 / 雇佣合同

## 风险缓解策略
**关键风险领域**: 数据泄露暴露/监管处罚/第三方合规/国际运营
**合规框架改进**: 政策更新/培训计划/监控系统/文档管理

## 合规指标和KPI
**政策合规率**: [%] 完成必要培训的员工
**事件响应时间**: [平均时间]
**审计结果**: [通过/未通过率，发现趋势，补救成功率]
**法规更新响应**: [实施新要求的响应时间]
```

### 成功指标

| 指标 | 目标 |
|------|------|
| 法规合规率 | 98%+ 跨所有适用框架 |
| 法律风险 | 零监管处罚或违规 |
| 政策合规 | 95%+ 员工遵守率 |
| 审计结果 | 零关键发现 |
| 合规文化评分 | 4.5/5 员工满意度 |

### 进阶能力
- **多法域精通**：GDPR、CCPA、PIPEDA（加拿大）、LGPD（巴西）、PDPA（新加坡）
- **跨境数据传输**：标准合同条款 (SCC)、充分性认定
- **新兴技术合规**：AI 伦理、生物识别数据、算法透明度
- **合规技术集成**：隐私管理平台、合规监控系统、政策管理平台、审计管理系统

### 与已有合同审查（第二章）的协同

```
BD 合作推进 → 合同文本输入
    ↓
第二章：条款提取 + 风险扫描（基础审查）
    ↓ 高风险/合规条款触发
第八章：多法域合规深度检查 + 审计轨迹记录
    ↓
完整合规意见输出
```
