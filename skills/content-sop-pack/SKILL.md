## 一、Execution SOP（执行流程）

### 内容生产流水线

每条内容必须经过以下 7 步流水线：

```
选题确认 → 3秒钩子 → 结构搭建 → 正文撰写 → 自检修正 → 平台适配 → 发布输出
```

### Step 1: 选题确认
输入：Lead SOP 输出的选题池（`relay/`）
检查项：
- 热度评分 ≥ 70/100
- 与品牌/产品相关度 ≥ 60/100
- 未被本周已发布内容覆盖（检查 Obsidian `报告/内容Agent·发布排期.md`）
- 有差异化角度（非简单复制竞品）

### Step 2: 3秒钩子
所有平台的内容头部必须完成：
- 小红书：前 3 行制造悬念/痛点/冲突
- 短视频：前 3 秒设置钩子画面+文案
- 公众号：标题+摘要覆盖搜索意图
- SEO：H1 包含核心关键词

### Step 3: 结构搭建
```
[钩子] → [价值铺垫] → [核心内容] → [情绪高潮] → [CTA]
```

不同平台结构权重：
| 平台 | 钩子 | 价值 | 核心 | 情绪 | CTA |
|------|------|------|------|------|-----|
| 小红书 | 30% | 20% | 30% | 10% | 10% |
| 公众号 | 15% | 25% | 40% | 10% | 10% |
| 短视频 | 40% | 10% | 25% | 15% | 10% |
| SEO | 10% | 20% | 50% | 5% | 15% |

### Step 4: 正文撰写
- 遵循墨麟品牌调性（参考品牌指南）
- 每段不超过 3 行（手机阅读优化）
- 关键数据必须标注来源
- 避免绝对化用语（"最"、"第一"、"绝对"、"100%有效"）
- 包含至少 1 个互动引导（评论/点赞/收藏）
- ⚡ 合规预检（2026-05-17 新增）：撰写完成后立即执行合规检查——
  1. 扫描敏感词（政治/医疗/金融相关未授权用语）
  2. 检查绝对化用语（"最好"、"最佳"、"第一"等）
  3. 验证数据来源可查（无 AI 幻觉数据）
  4. 确认无竞品贬低/虚假宣传
  5. 标记高风险段落后在文中用 `[⚠合规待确认]` 标注
  合规预检结果记录在输出 frontmatter 的 `compliance_precheck` 字段中

### Step 5: 自检修正（强制步骤）
对照 QA SOP 逐项自检评分。评分结果写入内容文件头部：
```yaml
qa_score: 85
qa_checks:
  brand_consistency: 90
  compliance: 95
  conversion: 80
  data_truth: 85
  seo: 75
  platform_fit: 90
  originality: 80
```

### Step 6: 平台适配
同一内容按平台自动改写：

| 平台 | 改写方向 | 特殊要求 |
|------|----------|----------|
| 小红书 | 情绪化+短段落+emoji | 每篇必配 3-6 张图 |
| 公众号 | 深度化+结构化 | 可加副标题 |
| 抖音 | 冲突化+口语化 | 控制在 60s 以内 |
| Vocus | 个人化+观点鲜明 | 繁体本地化 |
| LINE | 简讯化+强CTA | 严格控制 200 字以内 |
| SEO 站点 | 结构化+关键词密集 | H2-H3 层级+内链 |

### Step 7: 发布输出
输出格式统一：
- 内容正文 → `relay/{platform}_content_{timestamp}.md`
- 元数据 → 同文件 frontmatter（含 qa_score、platform、target_audience、compliance_precheck、model）
- 发布状态 → 写入 Obsidian `报告/内容Agent·发布排期.md`（v3.0 平坦结构，所有报告在 `报告/` 根目录）

### CTA 优化指南（2026-05-17 新增）
不同平台 CTA 适配策略：
- 小红书：CTA 放在正文最末尾 + 评论区置顶，使用"你会...吗？"、"评论区告诉我"等低压力引导
- 公众号：CTA 放在文末分隔线后，使用"点击关注"、"在看+转发"等行动指令
- 抖音：CTA 放在最后 3 秒口播+画面叠加，使用"关注我"、"下期讲..."等留存导向文案
- SEO：CTA 放在内容中部，使用"免费获取"、"点击了解"等价值导向文案
目标：全局 CTA 完成率 ≥ 85%

## 二、QA SOP（质检流程）

### 评分矩阵

| 维度 | 权重 | 检查项 | 扣分规则 |
|------|------|--------|----------|
| 品牌一致性 | 20% | 调性匹配、术语正确、视觉一致 | 每处偏离 -5 |
| 合规风险 | 20% | 敏感词、竞品贬低、虚假宣传、政策红线 | 每项 -20，触及红线直接 0 分 |
| 转化能力 | 15% | CTA 是否明确、紧迫感、价值展示 | 无 CTA -10，不明确 -5 |
| 数据真实性 | 15% | 数据来源可查、无数字幻觉、引文准确 | 每个幻觉点 -10 |
| SEO 结构 | 10% | 关键词密度、H 标签、内链 | 缺失核心词 -5 |
| 平台适配 | 10% | 格式、长度、emoji、话题标签 | 每处不适配 -3 |
| 原创性 | 10% | 非简单改写的差异化角度 | 同质化严重 -8 |

### 评分执行
```
总分 = Σ(维度得分 × 权重)
```

### 阈值动作
| 分数范围 | 动作 | 说明 |
|----------|------|------|
| ≥ 85 | ✅ 直接输出 | 高质量，无需修改 |
| 70-84 | 🔄 自动修正 | 修正低分维度后输出 |
| 60-69 | ⚠️ 人工确认 | 触发 Escalation SOP L1 |
| < 60 | 🚫 打入待人工审核 | 触发 Escalation SOP L2 |

### 自动修正策略
- 品牌一致性低 → 重新匹配品牌词库
- 转化能力低 → 强化 CTA
- SEO 结构低 → 调整关键词布局
- 平台适配低 → 按平台规范改写

## 三、Escalation SOP（升级流程）

### 触发条件与动作

| # | 场景 | 触发条件 | 动作 | 治理级别 |
|---|------|----------|------|----------|
| 1 | QA 连续不达标 | 同一任务连续 3 次 QA < 70 | 暂停该任务线，写复盘到 Obsidian | L2 审批 |
| 2 | 合规红线 | 检测到敏感/违规内容 | 立即撤回，锁定内容，飞书告警 | L2 审批 |
| 3 | 平台封号/限流 | API 返回 403/限流码 | 自动切换备用账号，记录异常 | L1 通知 |
| 4 | AI 幻觉疑点 | 数据来源无法验证，置信度 < 60% | 标记为"待验证"，不直接引用 | L1 通知 |
| 5 | 成本异常 | 单次任务 Token 消耗 > 阈值 200% | 自动降级模型，记录成本审计 | L1 通知 |
| 6 | 飞轮断裂 | 上游 relay 文件缺失 > 90分钟 | 飞书告警"内容飞轮断裂" | L1 通知 |

### 升级通信格式

所有 Escalation 通过飞书发送，格式：
```
🚨 [内容Agent] {场景名称}
━━━━━━━━━━━━━━━
触发时间：{时间}
任务ID：{task_id}
内容摘要：{前50字}
QA评分：{分数}
风险等级：{L0-L4}

操作建议：{action}
━━━━━━━━━━━━━━━
```

## 四、Cron 经营节奏

### 日节奏（内容 Agent）

| 时间 | 任务 | 类型 | 输出 |
|------|------|------|------|
| 06:30-07:30 | 情报层：行业热点 + 竞品内容扫描 | Intel | relay/intel_{date}.json |
| 08:00-09:00 | 选题会：从 intel 池筛选 TOP5 选题 + 排期 | Planning | 写入 Obsidian 排期 |
| 09:00-10:30 | 内容生产：执行 SOP 全流水线 | Execution | 产出稿 → relay/ + QA 评分 |
| 10:30-11:30 | 分发层：平台适配 + 定时发布 | Distribution | 各平台发布 |
| 22:00 | 复盘层：内容表现复盘 + QA 趋势 | Feedback | 写入 Obsidian `报告/银月｜内容经营复盘·{date}.md` + relay/data/daily_review_{date}.json |

#### 22:00 复盘数据链

复盘 Cron 需消费多个上游数据源，按以下顺序执行：

```
                                     ┌──────────────────────────┐
                                     │ relay/kpi/*_{date}.json   │ ← 各Agent日KPI（全天陆续写入）
                                     └─────────┬────────────────┘
                                               │
                                     ┌─────────▼────────────────┐
                                     │ relay/data/daily_        │
                                     │ summary.json             │ ← 墨测数据·21:50 Cron（跨业务聚合+±2σ异常检测）
                                     └─────────┬────────────────┘
                                               │
                                     ┌─────────▼────────────────┐
                                     │ 22:00 复盘 Cron          │ ← 本步骤
                                     │                          │
                                     │ ① 读取 relay/kpi/ 获取KPI│
                                     │ ② 读取 daily_summary.json│
                                     │    获取跨业务上下文      │
                                     │ ③ QA趋势分析              │
                                     │ ④ KPI连续下降检测(3日)    │
                                     │ ⑤ 异常审计                │
                                     │ ⑥ Gatekeeper终检          │
                                     └──────┬───────────────────┘
                                            │
                        ┌───────────────────┼───────────────────┐
                        ▼                   ▼                   ▼
              ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
              │ 报告/银月｜内容   │ │ relay/data/     │ │ relay/kpi/      │
              │ 经营复盘·{date}.md│ │ daily_review_   │ │ content_writer_ │
              │ (Obsidian复盘)   │ │ {date}.json     │ │ {date}.json     │
              └─────────────────┘ │ (复盘元数据)    │ │ (存在则跳过)     │
                                  └─────────────────┘ └─────────────────┘
```

注意点：
- `relay/data/daily_summary.json` 由墨测数据 Cron 在 21:50 自动写入，复盘前确认其存在——它提供跨业务线聚合数据、±2σ 异常检测结果、以及 `day_over_day` 环比变化
- 每日 KPI 数据（`relay/kpi/content_writer_{date}.json`）可能在复盘之前已由内容 Agent 自行写入——如果已存在则跳过写入，仅读取
- 复盘元数据写入 `relay/data/daily_review_{date}.json`（复盘执行结果 JSON，包含 gatekeeper 终判和明日优先级）

### 周末模型路由策略（2026-05-17 新增）

周末任务量减少时，按以下规则降级模型以控制成本：
1. 紧急性低（排期 > 48h）→ 使用 GPT-4.1 mini / DeepSeek 等低成本模型
2. 紧急性高（排期 < 24h）→ 维护主力模型（GPT-4.1 / Claude 4 Sonnet）
3. 单人执行（字数 < 500）→ 优先使用低成本模型
4. 重要平台（品牌头条/深度文章）→ 无论何时都使用主力模型
5. 所有任务仍需通过 QA SOP，降级模型版本需在 frontmatter 标注 `model: gpt-4.1-mini`

### 周节奏

| 时间 | 任务 | 输出 |
|------|------|------|
| 周日 21:00 | 内容经营周报 | 写入 Obsidian `报告/` |
| 周日 21:30 | 增长实验生成 | AB 测试方案 → `relay/experiments/` |
| 周一 09:00 | 选题会（带周报） | 本周排期 → Obsidian `报告/内容Agent·发布排期.md` |

## 五、小红书 Specialist 工作流（吸收自 agency-agents）

> 源：[Xiaohongshu Specialist](https://github.com/msitarzewski/agency-agents/blob/main/marketing/marketing-xiaohongshu-specialist.md) · MIT License · 吸收日期：2026-05-17

### 平台定位

你是一个小红书营销大师，对生活方式趋势有敏锐的嗅觉。你的核心能力是**趋势骑乘 + 审美一致性 + 真实叙事 + 社区优先**。

### 小红书内容策略

| 策略 | 说明 |
|------|------|
| **生活方式品牌开发** | 创建有说服力的生活方式叙事，与潮流敏感的受众共鸣 |
| **趋势驱动内容** | 识别新兴趋势，将品牌定位在潮流前方 |
| **微内容优化** | 优化短内容（笔记/故事）的算法可见性和分享性 |
| **社区互动** | 通过真实互动和 UGC 裂变建立忠诚社群 |
| **转化导向** | 将生活方式互动转化为可量化的业务结果 |

### 小红书算法规则

```
完成率 > 点赞 > 收藏 > 评论 > 分享（权重递减）

黄金前 3 行：
• 第 1 行：制造悬念/痛点/冲突
• 第 2 行：暗示价值/答案在後面
• 第 3 行：引导点击「展开」

格式节奏：
• 每段 ≤ 3 行（手机阅读）
• 3-6 张图 + 1 张封面
• emoji 密度 2-3 个/段
• 话题标签 3-5 个（含 1 个长尾词）
```

### 内容组合比例

```
70% 有机生活方式内容（种草/日常/教程）
20% 社区互动内容（提问/投票/征集/UGC）
10% 直接转化内容（限时优惠/产品推荐）
```

### 品牌审美一致性检查

- ✅ 所有笔记有统一的视觉风格（色调/滤镜/字号/布局）
- ✅ 封面图风格一致（一眼认出是同一品牌）
- ✅ 文案语气一致（保持同一人格）
- ❌ 禁止纯产品图堆砌（必须融入生活场景）
- ❌ 禁止硬广语气（小红书用户排斥硬推）

## 六、抖音 Strategist 工作流（吸收自 agency-agents）

> 源：[Douyin Strategist](https://github.com/msitarzewski/agency-agents/blob/main/marketing/marketing-douyin-strategist.md) · MIT License · 吸收日期：2026-05-17

### 核心哲学

抖音的核心不是「把视频拍好看」，而是「**前 3 秒抓住注意力，让算法替你分发**」。

### 短视频内容策划

- **高完播率结构**：黄金 3 秒钩子 + 信息密度 + 结尾悬念
- **内容矩阵**：教育型/剧情型/测评型/Vlog，四种格式轮换
- **节奏控制**：卡点剪辑/转场/字幕节奏协同
- **默认要求**：每条视频必须有明确的完播率优化策略

### 抖音算法优先级

```
完播率 > 点赞率 > 评论率 > 分享率（算法权重递减）

前 3 秒决定一切 — 不铺垫，直接抛冲突/悬念/价值
视频时长按内容类型匹配：
  知识干货 30-60s
  剧情内容 15-30s
  直播切片 15s
❌ 绝对禁止在视频内引导到外部平台（触发限流）
```

### 直播电商方法论

```
直播间搭建 → 场景/灯光/设备清单
直播脚本设计：
  开场留人钩子 → 商品讲解 → 逼单收尾 → 下播转款
直播节奏控制：
  每 15 分钟一次流量峰值循环
直播数据复盘：
  GPM（千次观看成交额）/ 平均观看时长 / 转化率
```

### 投流策略

- DOU+：人群定向精准度 > 投放金额
- 千川投流：短视频引流 + 直播引流协同
- 矩阵号运营：主号 + 子号 + 员工号协同

### 合规红线

- ❌ 绝对化用语（「最好」「第一」「100%有效」）
- ❌ 食品/药品/化妆品类别必须符合广告法规
- ❌ 直播中禁止虚假承诺或夸大宣传
- ❌ 未成年出镜需监护人陪同

### 抖音节奏日报模板

```
上午 08:00 — 数据复盘（昨日播放量/完播率/互动）
上午 09:00 — 选题策划（结合热点宝/巨量创意）
上午 10:00 — 脚本创作
下午 14:00 — 拍摄/剪辑
下午 18:00 — 发布（高峰时段）
晚上 20:00 — 互动维护（回复评论）
```

## 八、Bilibili Strategist 工作流（吸收自 agency-agents）

> 源：[Bilibili Content Strategist](https://github.com/msitarzewski/agency-agents/blob/main/marketing/marketing-bilibili-strategist.md) · MIT License · 吸收日期：2026-05-18

### 平台定位

B 站是中国最具文化特色的视频社区平台。核心哲学：**尊重社区、弹幕至上、质量优先**。B 站用户高度挑剔，不真实的内容会被瞬间识破并拒绝。

### B 站独特生态

| 要素 | 说明 |
|------|------|
| **弹幕文化** | 弹幕是 B 站灵魂——不是干扰，而是互动资产。每条视频要在故事板阶段就设计弹幕触发点 |
| **三连机制** | 点赞+投币+收藏。三连是 B 站最高认可，内容需引导但不乞求 |
| **粉丝勋章** | 粉丝勋章体系 + 充电（打赏）+ 舰长/提督/总督（付费会员） |
| **长视频优先** | B 站奖励深度长内容而非快速发布。10-20 分钟深度视频是支柱内容 |
| **内容分区** | 知识区/科技区/生活区/美食区/游戏区/动画区——不同分区有不同成功模式 |

### B 站内容策略

```
内容组合比例：
  40% 支柱内容（深度长视频，10-20min，高制作价值）
  30% 热点内容（热点回应/梗融入/时效评论）
  20% 社区内容（Q&A/粉丝互动/幕后花絮）
  10% 实验内容（新格式/合作/直播）

推荐池升级路径：
  初始流量池 → 互动达标 → 二级推荐池（1万+播放）→ 热门推荐 → 每周必看
```

### B 站算法权重

```
完播率 > 互动率（弹幕+评论+三连）> 投币率（权重最高单操作）

封面是 CTR 第一因素：
  • 高对比、手机缩略图尺寸可见
  • 面部或表现性角色出现（+30% CTR）
  • 文字叠加最多 8 字、粗体
  • 色彩搭配匹配频道品牌
  • 通过「滚动测试」——在 20 个缩略图中能跳出来

标题公式模板：
  • 【分区标签】好奇心钩子 + 具体细节 + 情感锚点
  • 示例：【硬核科普】为什么中国高铁能跑 350km/h？答案让我震惊
```

### 弹幕交互设计

每条视频在故事板阶段必须设计弹幕触发点：

| 时间点 | 内容时刻 | 预期弹幕反应 |
|--------|----------|--------------|
| 0:03 | 标志性开场白 | 社区口头禅刷屏 |
| 2:15 | 惊人事实揭露 | 「？？？」和震惊反应 |
| 5:30 | 互动提问 | 观众在弹幕中回答 |
| 8:00 | 回溯旧视频 | 老粉识别 |
| 结尾 | 收尾仪式 | 「下次一定」/ 告别语 |

**弹幕「播种」策略：**
- 发布后第 1 小时准备 10-15 条「种子弹幕」
- 包含时间戳特定评论引导互动模式
- 植入幽默回溯建立内部梗

### 恰饭（品牌合作）规范

B 站观众对商业化内容接受度正在提升，但要求极高：
- ✅ 品牌植入内容首先为观众提供价值，而非硬广
- ✅ 坦诚告知是赞助内容（B 站观众尊重诚实）
- ✅ 通过花火平台规范化品牌合作
- ❌ 避免生硬口播——融入内容叙事
- ❌ 避免过度商业化——保持内容价值优先

### B 站节奏日报

```
上午 09:00 — 数据复盘（昨日播放/完播率/弹幕密度/三连率）
上午 10:00 — 选题策划（结合热门/每周必看/入站必刷）
下午 14:00 — 内容制作（弹幕触发点嵌入故事板）
```

## 九、微信公众号 Manager 工作流（吸收自 agency-agents）

> 源：[WeChat Official Account Manager](https://github.com/msitarzewski/agency-agents/blob/main/marketing/marketing-wechat-oa-manager.md) · MIT License · 吸收日期：2026-05-18

### 平台定位

微信公众号是中国最亲密的商业沟通渠道。核心哲学：**公众号不是广播频道，而是关系建设工具**。你是在建立真实的订阅者关系，而非推送消息。

### 订阅号 vs 服务号

| 维度 | 订阅号 | 服务号 |
|------|--------|--------|
| 推送频率 | 每天 1 次（折叠在订阅号文件夹） | 每月 4 次（直接显示在聊天列表） |
| 适用场景 | 内容营销、品牌建设、日常互动 | 客服、交易通知、会员服务 |
| 消息可见性 | 低——折叠，需用户主动打开 | 高——直接出现在对话列表 |
| 菜单能力 | 支持 | 支持 + 更丰富的 API |
| 模板消息 | 不支持 | 支持（服务通知） |
| 微信支付 | 需认证后可接入 | 支持 |

**选择策略：** 内容驱动型品牌 → 订阅号；服务驱动型品牌 → 服务号；资源允许 → 双号矩阵

### 内容标准

```
内容组合比例（60/30/10 法则）：
  60% 价值内容（教育/干货/行业洞察）
  30% 社区/互动内容（投票/问答/UGC 征集）
  10% 推广内容（产品/活动/促销）

发布频率：大多数企业每周 2-3 篇
发布时机：工作日早 8:00-9:00 或晚 20:00-22:00（通勤/睡前阅读高峰）
```

### 48 小时互动窗口

**关键规则：** 用户与公众号互动后（发消息/点击菜单/扫码），公众号在 48 小时内可以主动推送消息给该用户。48 小时后窗口关闭，只能通过模板消息（服务号）触达。

**窗口运营策略：**
- 用户首次关注 → 48h 内发送欢迎序列（品牌介绍 + 价值主张 + 引导互动）
- 用户点击菜单 → 48h 内推送相关内容
- 用户参与活动 → 48h 内发送后续跟进
- 窗口关闭后 → 依赖模板消息（服务号）或菜单/自动回复被动触达

### 粉丝分层与精细化运营

| 层级 | 定义 | 运营策略 |
|------|------|----------|
| **新关注** | 7 天内关注 | 48h 窗口欢迎序列，引导菜单使用，建立首次价值认知 |
| **活跃粉丝** | 月互动 ≥ 3 次 | 深度内容推送，优先参与内测/活动，培育为种子用户 |
| **沉默粉丝** | 30 天无互动 | 情感唤醒内容，限时福利激活，必要时清洗 |
| **付费用户** | 有购买记录 | 专属服务通道，VIP 内容，售后关怀，复购引导 |
| **KOC** | 主动分享/推荐 | 品牌大使计划，共建内容，专属社群 |

### 菜单优化

```
一级菜单（最多 3 个）结构建议：

「发现价值」           「与我互动」           「专属福利」
  ├ 精选文章            ├ 联系客服             ├ 会员中心
  ├ 品牌故事            ├ 加入社群             ├ 限时活动
  ├ 产品/服务           ├ 商务合作             ├ 我的订单
  └ 搜索历史            └ 我要投稿             └ 积分商城

菜单优化检查清单：
  □ 每个一级菜单下的二级菜单 ≤ 5 个
  □ 最高频操作放在最前
  □ 菜单名称 ≤ 4 个字
  □ 有明确的 CTA（行动指引）
  □ 每月查看菜单点击数据，优化排序
```

### 自动回复体系

| 类型 | 用途 | 示例 |
|------|------|------|
| 被关注回复 | 首次关注自动推送 | 品牌介绍 + 价值主张 + 菜单引导 + 引导回复关键词 |
| 关键词回复 | 用户发送特定词触发 | 「合作」→ 商务联系方式，「课程」→ 产品介绍 |
| 消息回复 | 非关键词匹配的兜底 | 「已收到你的消息，客服会在工作时间回复」 |

### 关键成功指标

- 打开率 > 30%（行业平均 20-25%）
- 文章内链接点击率 > 5%
- 文章完读率 > 50%

- 菜单周点击率 > 20%（关注者中使用自定义菜单的比例）
- 内容驱动转化率 2-5%

## 十、知乎 Strategist 工作流（吸收自 agency-agents）

> 源：[Zhihu Strategist](https://github.com/msitarzewski/agency-agents/blob/main/marketing/marketing-zhihu-strategist.md) · MIT License · 吸收日期：2026-05-18

### 平台定位

知乎是中国最权威的知识分享平台。核心哲学：**在知乎，可信度比粉丝数重要得多**。权威和真实专业度 > 粉丝数或推广力度。你是在建立思想领导力，而非做营销号。

### 盐值体系

知乎「盐值」是衡量用户社区贡献的综合信用分，基于：
- **内容质量**（回答的赞同/感谢/收藏）
- **社区建设**（举报/众裁/公共编辑）
- **行为规范**（是否违规被处罚）
- **身份真实性**（实名认证/机构号认证）

**盐值影响：** 高盐值用户的回答在搜索和推荐中获得更高权重，是知乎 SEO 的核心。

### 专业回答结构

```
知乎高质量回答的标准结构：

[0-50 字] 一句话结论——开门见山，让读者立刻知道你要说什么
[50-150 字] 背景/问题界定——为什么这个问题重要
[150-800 字] 核心论述（分 3-5 个要点）
  • 要点 1：论据 + 数据/案例
  • 要点 2：论据 + 数据/案例
  • 要点 3：论据 + 数据/案例
[800-1000 字] 总结提炼 + 延伸思考
[结尾] 温和的 CTA（引导关注专栏/赞同/讨论）

不可缺元素：
  □ 数据来源引用（知乎极度重视可查证性）
  □ 至少 1 张配图/表格（增强可读性和可信度）
  □ 分点/小标题（便于手机阅读）
```

### 知乎核心功能矩阵

| 功能 | 说明 | 适用场景 |
|------|------|----------|
| **圆桌** | 主题讨论活动，邀请嘉宾参与 | 行业热点深度讨论，品牌思想领导力展示 |
| **专栏** | 持续发布系列文章，积累订阅者 | 核心阵地——6 个月滚动内容计划，每周 1-2 篇 |
| **电子书** | 将最佳回答汇编为出版物 | 额外的权威信号，内容资产沉淀 |
| **知乎 Live** | 实时语音分享 + 互动问答 | 深度触达最活跃粉丝，知识付费 |
| **盐选专栏** | 付费内容产品，平台推荐分发 | 知识变现，高质量流量获取 |
| **圈子** | 社区讨论组 | 粉丝社群运营 |

### 选题与回答策略

**问题选择框架（高影响力问题 5 维评分）：**

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 流量潜力 | 25% | 问题关注人数、浏览量趋势 |
| 商业相关度 | 30% | 与品牌/产品/服务的关联度 |
| 竞争程度 | 15% | 现有回答数量与质量 |
| 差异化空间 | 20% | 能否提供独特视角/新数据 |
| 时效性 | 10% | 社会热点/行业事件绑定 |

**回答禁忌：**
- ❌ 只回答有真正专长领域的问题（可信度是一切）
- ❌ 禁止攻击性推销语言——让专业度和价值说话
- ❌ 避免短回答——最低 300 字，通常需要 800-2000 字才显示专业度
- ❌ 不要忽视评论区——深度参与讨论是建立关系的关键

### 关键成功指标

- 平均赞同 > 100/回答（质量信号）
- 50%+ 回答出现在搜索前 3 结果
- 30%+ 回答成为「最佳回答」
- 专栏月新增订阅 500-2000
- 20%+ 读者通过评论进行互动
- 月新增关注 100-500
- 每月 50-200 条有效线索
- 内容驱动线索转化 10-30%

```

每日 14:00 — 撰写/优化回答
每周一     — 专栏文章发布
每周五     — 数据分析（赞同趋势/可见性/互动率）

```
