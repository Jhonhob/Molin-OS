## 二、🔴 P0 改进提案 #1：KPI 数据管道容错机制

### 问题描述

content_writer Cron 执行第5步（KPI写入）自5月19日起静默失败。无任何告警。22个Agent连续5+天零KPI，导致：
- 财务分析 (墨算) 无法进行 WoW 对比
- 零成本追踪 → 无法判断 API 预算阈值 (80%/95%)
- 品控闭环中断 → QA 评分无记录

### SOP 改进提案

**新步骤: KPI写入容错门控**

在现有 Cron SOP KPI写入步骤之后增加：

```yaml
Step 5b: KPI 写入验证门控
- 写入后立即验证：relay/kpi/{agent}_{today}.json 是否存在
- 若不存在 → 立即重试 (3次，间隔30秒)
- 3次失败 → 告警级别提升，写入 fallback JSON 到 relay/kpi/{agent}_{today}.fallback.json
- 触发飞书 L1 通知: "KPI管道告警 - {agent} - {date}"
- 每日 22:00 墨数清洗时检测所有 fallback 文件并上报

Step 5c: KPI健康巡检
- 每个Cron执行前检查：relay/kpi/ 下最近日期是否 >= 昨天
- 若缺失 → 不执行主任务，先执行 KPI 追溯管道
```

**验收标准**: 连续7天无 KPI 空白日；单次写入失败后30秒内完成自愈。

## 三、🔴 P0 改进提案 #2：外部依赖容错框架

### 问题描述

小红书 Cookie 自5月18日失效后，内容发布管道 (broken_cookie) 完全阻塞。无自动续期、无告警、无 fallback 发布通道。

### SOP 改进提案

**新步骤: 外部认证依赖生命周期管理**

```yaml
Step 1: 健康检查 + 自动续期
- 每次内容发布前，检测 Cookie 有效性 (测试发布API)
- Cookie 失效 → 自动尝试续期（Playwright 重新登录）
- 续期失败 → 触发飞书 L1 通知 + 降级到备用发布通道

Step 2: 多通道 Fallback
- 主通道: 小红书（Cookie 认证）
- 备用通道: 内容存入 `产出/银月｜就绪待发布.md` 标记 📌
- 终级通道: 手动发布清单写入 Obsidian

Step 3: 定期续期
- Cron: 每天 06:00 检查所有发布平台 Cookie 有效性
- Cookie 剩余有效期 < 3天 → 提前续期
```

**验收标准**: Cookie失效后30分钟内自动恢复或完成降级；无内容因发布管道阻塞而损失超过24小时。

| 维度 | 详情 |
|------|------|
